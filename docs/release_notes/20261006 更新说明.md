# 20261006 更新说明（20261005 至 20261006）

## 更新重点

解决 GDN + DFlash2 触发的问题。

- 回移 GDN 首次单 token prefill 状态初始化修复：用 CPU 调度信息识别首次 chunk，即使 query_len=1 也走 prefill、屏蔽复用缓存的旧状态；续算的单 token chunk 和 graph capture 仍走 decode，尾部 padding 不计入 prefill 请求数和 token 数。
- 修复卷积 prefill/decode 交接时的历史窗口：prefill 只读取和更新缓存头部 `width-1` 个逻辑历史槽，保留扩展物理窗口中的 speculative scratch。当前 xthd 核 width=4，历史长度恒为 3；不再把 DFlash2/spec5 的 8 槽物理容量当作历史长度。
- 插件同步传入首次 chunk 的 CPU mask，更新 `GDNAttentionMetadataBuilder.build` 的来源指纹和审计记录。部署需同时包含 vLLM、torch_xcpu 和插件配套提交，并重新编译安装 torch_xcpu。

## torch_xcpu 算子变更

统计范围为上一版基线 `acb6116a9ffee95d67554fb1e884548c2053abc6`（不含，2026-10-05）至 `dd4d3781f6ae78903503c5c08cc10fb097ccc6fd`（含，2026-10-06）。以下测试用于佐证行为，不代表覆盖全部 shape、dtype、后端和并行组合。

- `causal_conv1d_fn`（小修改）：xthd prefill 核将历史长度从 `args->state_len` 的物理容量改为 `width-1`，当前 width=4 时仅使用前 3 槽。conv_states 仍按 `[num_cache_lines, dim, physical_state_len]` 的逻辑形状、原有物理 stride 访问；有初始状态时从头部历史槽读取，长 chunk 写最后 3 个输入，短 chunk 拼接旧历史（无初始状态则补零）后更新头部。其余 speculative scratch 和无关 cache block 不写。Torch schema、参数结构、dtype 和 launch 调度未变；扩展缓存的读取/更新语义改变，NPU prefill 实现必须与 speculative decode 的历史位置同步。

  - commit `7519361dab3a9472fba7d313ccf166e313083cb8`：[GDN] Preserve logical prefill history in speculative conv caches
  - 测试：`torch_xcpu/test/ops/custom_ops/test_causal_conv1d_update_xthd.py` 新增整段及 `(5,5)`、`(1,2,7)` 分块 prefill 到 speculative decode 交接，覆盖 FP32/BF16/FP16，断言历史前缀、scratch 和无关 block；`torch_xcpu/test/ops/custom_ops/test_causal_conv1d.py` 修正扩展状态 reference，只读取/写入历史前缀。decode 算子实现本区间未修改，不作为独立变更项。

- `allocate_gdn_metadata_outputs`（小修改）：底层 Torch schema 在 `chunk_size` 后新增末尾可选参数 `Tensor? no_prior_state_cpu=None`，C++ 签名同步扩展。传入时必须是 CPU bool 一维向量 `[batch_size]`，按 stride(0) 同步读取。无 speculative decode 时，`query_len>1` 或 `query_len>0 && mask[row]` 的首行开始按 prefill 分配，首次单 token chunk 也会分配 has_initial_state、chunk 和 conv 元数据。返回的 22 项输出顺序不变，各次 build 仍独立分配。旧底层直调省略新参数可用，但不能获得首次单 token 的新判定；新插件显式传入该参数，必须安装新 schema。需同步检查 NPU 分配路径，不能只改构造路径。

  - commit `dd4d3781f6ae78903503c5c08cc10fb097ccc6fd`：[GDN] Initialize stateless first chunks in fused metadata
  - 接入 commit `5063475dff978ac4d865004a053f308fcf662243`：[GDN] Initialize first chunks in XCPU metadata and record backport audit
  - 测试：`vllm-xcpu-plugin/tests/plugin_tests/test_gdn_patch.py` 扩展 CPU/MCPU 逐字段对照，覆盖首次/续算 chunk、none/align/all 缓存模式、strided 输入与 graph padding；torch_xcpu 未新增独立 allocator 专项测试文件。

- `build_gdn_metadata_out`（小修改）：底层 Torch schema 在 `outputs` 后新增同样的末尾可选参数 `Tensor? no_prior_state_cpu=None`，C++ 签名同步扩展。使用与 allocator 相同的 CPU bool mask 和 stride 契约；无 speculative decode 的分支用相同规则划分 prefill，剔除尾部零长度 padding 后重算 prefill token 数。首次单 token prefill 得到 has_initial_state=False，避免读取复用状态。device 元数据 kernel、从核参数结构和输出顺序未变，本次修改在 C++ 元数据包装层。插件计算 `mask=(query_len>0) & (seq_len_cpu_upper_bound<=query_len) & is_prefilling`，将同一 mask 传给分配和构造；缺少 prefill 标记时传 None。旧直调可省略，新接入必须两条路径一起更新并重编。

  - commit `dd4d3781f6ae78903503c5c08cc10fb097ccc6fd`：[GDN] Initialize stateless first chunks in fused metadata
  - 接入 commit `5063475dff978ac4d865004a053f308fcf662243`：[GDN] Initialize first chunks in XCPU metadata and record backport audit
  - 测试：`vllm-xcpu-plugin/tests/plugin_tests/test_gdn_patch.py`；上游判定的回归证据为 `vllm/tests/v1/attention/test_gdn_metadata_builder.py`，覆盖首次/续算单 token、缺少 prefill 标记、尾部 padding 和 graph capture。torch_xcpu 未新增独立 builder 专项测试文件。

补充核对：区间内 torch_xcpu_impl 只修改 `src/xthd/causal_conv1d_fn.cpp`，include/backends 无变化；另修改 `torch_xcpu/csrc/gdn_metadata.cpp` 和两份卷积测试。无新增独立算子、参数结构或实现文件，两个 metadata 接口均为已有 schema 的扩展。
