# 更新重点：
- vLLM 更新到 0.25，注意依赖库 openai 升级，附带了 openai-2.53.0-py3-none-any.whl
- 支持了 Qwen3.5/3.6 Prefix Cache
- 支持了 DFlash
- 初步支持 Qwen3.5/3.6 P/D 分离 KV-Cache 传输（仅 TP1）
- 消除了 GDN 所有情况的 python 回调，包括
	1. Decode only
	2. Prefill only
	3. Prefill-Decode Mix
	4. MTP Decode only
	5. MTP Prefill-Decode Mix
- 支持了 fp8 linear，使用较为复杂
	- 接入点参考该文件开头注释: torch_xcpu/torch_xcpu_impl/src/fp8_linear/acc_fp8_linear.cpp
	- 参考实现为
		- PortableFp8LinearLutKernel（使用 Lut 进行 FP8-BF16 转换，矩阵乘后 scale）
		- PortableFp8LinearDirectKernel（直接进行 FP8-BF16 转换，矩阵乘后 scale）
		- PortableFp8LinearPreScaledKernel（使用 Lut 进行 FP8-BF16 转换，矩阵乘前 scale）
	- 测试 torch_xcpu/test/ops/gemm_ops/test_fp8_linear.py
- 支持了 mxfp4 linear，使用较为复杂
	- 接入点参考该文件开头注释: torch_xcpu/torch_xcpu_impl/src/mxfp4_linear/acc_mxfp4_linear.cpp
	- 参考实现为
		- PortableMxfp4LinearLutKernel
	- 测试 torch_xcpu/test/ops/gemm_ops/test_mxfp4_linear.py
- 大幅度重构了 MoE，以 GroupGemm 为统一接口，支持 FP32 / BF16 / FP8 / MXFP4
	- BF16 接入点为：torch_xcpu/torch_xcpu_impl/src/moe_grouped_gemm/acc_bf16.cpp
	- FP8 接入点为：torch_xcpu/torch_xcpu_impl/src/moe_grouped_gemm/acc_fp8.cpp
		- 默认使用 AccFp8LinearKernel，也就是接上矩阵乘后即可用
	- MXFP4 接入点为：torch_xcpu/torch_xcpu_impl/src/moe_grouped_gemm/acc_mxfp4.cpp
		- 默认使用 AccMxfp4LinearKernel，，也就是接上矩阵乘后即可用
	- 测试 torch_xcpu/test/ops/gemm_ops/test_moe_grouped_gemm.py
- 中等幅度重构了 MPI EP 通信，目前后端包括
	- allgather-reducescatter，vllm 默认版本 torch 实现，调试用，不兼容 compile
	- torch alltoall，调试用
	- MPI v2，内部按目的地专家切分，alltoallv_put，发送后 topk=1
	- MPI v3，外部切分 token（sequence-parallel），alltoallv_put，发送后 topk=1
	- MPI v4 (0.25 暂不可用) ，外部切分 token，alltoallv，支持多轮滚动，用于大规模 EP Prefill，发送后 topk=1
	- MPI v5，外部切分 token（sequence-parallel），alltoallv，发送后 topk 完整保留，是 v6 的实验版
	- MPI v6 (尚未实现)，外部切分 token（sequence-parallel），alltoallv_put，发送后 topk 完整保留，适用于小规模 EP
- 已知情况下，所有精度 x 所有 EP 通信后端都可用

# torch_xcpu 算子变更：

统计范围为 2026-07-22（含）至 `c33f5e9f5d9895d169d7a4e96f749a0deb685bbb`。已有算子的扩展以 `torch_xcpu_impl` 中的初始算子名归类；具有独立参数结构和实现文件的新增算子保留完整名称。以下按发布时的最终实现整理；测试用于佐证行为，但不代表已覆盖全部 shape、dtype、后端和并行组合。

- `gumbel_sample`（小修改）：兼容 vLLM v0.25 的 padding request；`expanded_idx_mapping < 0` 时不再读取无效 request 的 temperature，也不写 `processed_logits_out`
	- commit `816a69da29b39a52893d02c8e1147c5b182a3e4a`：[Sampler] update gumbel_sample for vllm v0.25
	- 测试：`torch_xcpu/test/ops/custom_ops/test_gumbel_sample.py`
- `topk_softmax`（中等修改）：接口新增可选的 `is_padding: bool[num_tokens]`，并同步更新 Python fallback；调用方若传入该参数，需要同步从核签名
	- commit `f5a39bde2464026d0a1d9bc77f2bc94953cd8df0`：[MoE] update topk_softmax for vllm v0.25
	- 测试：`torch_xcpu/test/ops/custom_ops/test_topk_softmax.py`
- `reshape_and_cache`（大修改）：KV cache 从旧的 K/V 分面布局改为与 Triton attention backend 一致的单 Tensor 布局，典型 shape 为 `[num_blocks, num_kv_heads, block_size, 2 * head_size]`；随后将从核任务从按 token 切分改为按 `[token, head]` 切分，负 slot 从提前结束整个线程改为只跳过当前任务
	- commit `aa32bffa93ac9df96492840dde182f6676964ccb`：[Fix] Keep kv cache layout as triton attention backend (#32)
	- commit `c33f5e9f5d9895d169d7a4e96f749a0deb685bbb`：[Feat] Support DFlash for Qwen3.5 (#35)
	- 测试：`torch_xcpu/test/ops/custom_ops/test_reshape_and_cache.py`
- `reshape_and_cache_grouped`（新增算子）：一次调用处理多层 keys/values、多个 KV cache 和各自的 slot mapping，将原本逐层执行的 cache 写入合并为 grouped 调度；在 `torch_xcpu_impl` 中具有独立的参数结构、CPU launch 和从核实现，因此按完整算子名单列
	- commit `c33f5e9f5d9895d169d7a4e96f749a0deb685bbb`：[Feat] Support DFlash for Qwen3.5 (#35)
	- 测试：`torch_xcpu/test/ops/custom_ops/test_reshape_and_cache_grouped.py`
- `reshape_and_cache_mla`（中等修改）：从核任务从按 token 切分改为按 `[token, kv_c/pe component]` 切分，提高 token 数较少时的并行度；负 slot 从 `return` 改为 `continue`，避免同一线程后续有效 token 被一并跳过
	- commit `c33f5e9f5d9895d169d7a4e96f749a0deb685bbb`：[Feat] Support DFlash for Qwen3.5 (#35)
	- 测试：`torch_xcpu/test/ops/custom_ops/test_reshape_and_cache.py`
- `unified_attention`（大修改）：适配新的单 Tensor KV cache 布局；底层 Torch schema 随后新增必传 `causal` 参数，从核增加非 causal attention 路径。Python 包装层默认 `causal=True`，直接调用 `torch.ops.torch_xcpu.unified_attention` 的代码必须补参数
	- commit `aa32bffa93ac9df96492840dde182f6676964ccb`：[Fix] Keep kv cache layout as triton attention backend (#32)
	- commit `c33f5e9f5d9895d169d7a4e96f749a0deb685bbb`：[Feat] Support DFlash for Qwen3.5 (#35)
	- 测试：`torch_xcpu/test/ops/custom_ops/test_unified_attention.py`
- `fused_post_conv_prep`（中等修改）：输出 `beta` 固定为 FP32，不再跟随 `conv_output.dtype`
	- commit `9b38c3650ab1f9ea4a2383c2c4bd279a5a5176a7`：[GDN] update fused_post_conv_prep to match upstream vllm kernels, beta always need to be fp32
	- 测试：`torch_xcpu/test/ops/custom_ops/test_fused_post_conv_prep.py`
- `chunk_gated_delta_rule` 系列（中等修改）：`beta` 输入固定为 FP32；另修复 MTP 中 `chunk_gated_delta_rule_separated_custom_v2` 未按 `ssm_state_indices.stride(0)` 取索引的问题，使非连续/二维索引视图能正确寻址状态
	- commit `28b8cbc815870f917d3bc0e38ec7b812a1f1674c`：[GDN] update chunk_gated_delta_rule to match upstream vllm kernels, beta always need to be fp32
	- commit `541ae6329907f3209bdbe038aabbba6e10a99ade`：[Fix] Fix chunk_gated_delta_rule_custom in MTP case
	- 测试：`torch_xcpu/test/ops/custom_ops/test_chunk_gated_delta_rule.py`
- `fused_add_rms_norm`（中等修改）：新增 functional/out-of-place 接口 `fused_add_rms_norm_out`，同时保留原有会原地修改 `input` 和 `residual` 的接口；按初始算子名统一归入 `fused_add_rms_norm`
	- commit `76e3b78b0021d219e77c15a3cf5fd3b0232021ff`：[Norm] Add functional fused add RMSNorm kernel
	- 测试：`torch_xcpu/test/ops/custom_ops/test_fused_add_rms_norm.py`
- `causal_conv1d_fn`（大修改）：支持 aligned prefix cache；底层 schema 移除 `null_block_id`，新增 `block_idx_first_scheduled_token`、`block_idx_last_scheduled_token`、`initial_state_idx`、`num_computed_tokens` 和 `block_size_to_align`。Python 包装层仍接受 `null_block_id` 作为兼容别名，但直接调用底层 Torch op 的实现必须按新 ABI 修改
	- commit `5ef355a991c8ec69d2e923ef5fc8c1e3832d7103`：[GDN] update conv1d_fn to support aligned prefix-cache
	- 测试：`torch_xcpu/test/ops/custom_ops/test_causal_conv1d.py`
- `index_select_dim0`（小修改）：当 `num_indices == 0` 时直接返回，不再下发空任务，从而正确处理空 indices 并避免无意义的 kernel launch
	- commit `1ecd649816157aaa93dfea74d7146bf086c4f420`
	- 测试：`torch_xcpu/test/ops/test_index_select_dim0.py`
- `silu_and_mul`（小修改）：当 `num_rows == 0` 时直接返回，不再下发空任务
	- commit `1ecd649816157aaa93dfea74d7146bf086c4f420`
	- 当前版本未新增对应的空输入专项测试；现有基础测试位于 `torch_xcpu/test/ops/custom_ops/test_silu_and_mul_version_switch.py`
- `rms_norm`（中等修改）：输入 rank 从最多 3D 扩展到 2D～4D，并允许 2D weight；2D weight 的第 0 维必须与 input 第 0 维一致，用于 DFlash 的分组权重场景
	- commit `c33f5e9f5d9895d169d7a4e96f749a0deb685bbb`：[Feat] Support DFlash for Qwen3.5 (#35)
	- 测试：`torch_xcpu/test/ops/custom_ops/test_rms_norm_4d.py`
