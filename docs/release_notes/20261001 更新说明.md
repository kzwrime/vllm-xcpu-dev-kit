# 20261001 更新说明（20260930 至 20261001）

## 更新重点

- 从 vLLM v0.28 backport DFlash/DFlash2 更新/修复：
  - 新增 speculators 格式的 DFlash2 配置转换，按草稿配置读取 RoPE layout；DFlash2 和混合 sliding/full attention 草稿显式拒绝 V1 runner，目标辅助层选择使用总层数。此次是选定修复的回移，不是整体升级到 vLLM v0.28。
  - 修复草稿 KV 写入边界：拒绝的上下文后缀及 block ID=0 的 context/query 输出不可写 slot，seq_len 限制在 max_model_len 内；XCPU 元数据实现与 vLLM Triton 路径同步修正。
  - 草稿与目标的 Gumbel 随机流分离，草稿采样位置加 `1<<30`；自回归草稿的随机键独立推进，不依赖 RoPE position 是否冻结或被截断。插件适配新采样签名并更新上游兼容性 fingerprint。
  - 新增 `dflash2_selector_walk`，将真实模型 selector 接入迁到 torch_xcpu_impl，支持 greedy 和概率候选采样、FP32/FP64 噪声计算、请求级并行及 padding 请求跳过；候选噪声使用 token ID，输出保留原始 realized logits。
  - 修复 DP token padding 下草稿 attention 元数据：eager/PIECEWISE 使用实际 query token 数，FULL graph 使用捕获的 padding 形状。SWA 按 page budget 选择后端支持的最大对齐块，避免调度 KV block LCM 不必要膨胀；windowed DFlash 关闭 FlashAttention AOT schedule。
- MoE EP v5/v6 的 recv_topk_ids/weights 改为 `torch.empty`，由 unpack 完整写入有效行，省去容量尾部预填；算子实现和通信协议未改。可以消除两个 fill(-1)
- 开发套件新增 GLM-5.2 FP8/MXFP4 的 DFlash/DFlash2 eager/compile、单卡和 DP2/TP2 EP v5/v6 预设及回移影响文档。预设默认 5 个草稿 token、greedy draft

## torch_xcpu 算子变更

统计范围为上一版基线 `c497e76ecdd05d90aa59cc012f3712283293bc3d`（不含，2026-09-30）至 `38e7c39aa378b542263e85f71f57d2b8c5cbcdb8`（含，2026-10-01）。以下测试用于佐证行为，不代表覆盖全部 shape、dtype、后端和并行组合。

### 从核相关修改

- `dflash2_selector_walk`（新增算子）：新增独立 Torch schema、`DFlash2SelectorArgs` 和 impl 文件，CPU 直接计算，MCPU 单次异步 launch。输入按连续布局解释为 FP32 scores `[R,S,K,K]`、int64 candidates `[R,S,K]`、int64 positions 和 int32 states `[R,S]`，以及按 request state 索引的 FP32 temperatures/int64 seeds；原地写 int64 tokens `[R,S]` 与 FP32 realized scores `[R,S,K]`，Torch 返回 `()`。wrapper 校验同设备、连续性、dtype 和最小元素容量；调用方负责有效 state/候选 ID 及逻辑维度的一致性。每请求从 previous=0 起步，上一阶段选中列决定下一阶段分数行。概率模式按 `score/temperature + G(seed, position-1+2^30, candidate_token_id)` 选 token；温度零或 greedy 模式走 argmax，realized scores 始终保存原始分数，state<0 的请求不写输出。请求间可 OpenMP 并行，请求内步骤顺序执行；K=2/4/8/16/32/64/128 及模式/精度在 launch 外静态分派，其他 K 走通用实现。NPU 需实现新增参数和核，保持与 dense sampler 一致的 RNG 及草稿流分离语义。版本开关为 `TORCH_XCPU_DFLASH2_SELECTOR_WALK_IMPL`，默认 A0；B0 仅占位、没有计算，不能作为可用实现启用。插件改为直调 `torch.ops.torch_xcpu.dflash2_selector_walk`，旧 MCPU selector 未删除。

  - commit `117a6379378b72531a9033299114b5125af1bdd0`：[DFlash2] adapt dflash2 from vLLM v0.28 to support GLM-5.3-DFlash2
  - 接入 commit `188b1a5950a72cf1d5759544a1101a61847bc95b`：[DFlash] adapt XCPU sampling and KV preparation to upstream fixes
  - 测试：`vllm-xcpu-plugin/tests/fake_triton/test_dflash2.py`，既有 greedy K2 和新增概率 K16 对照稠密候选采样，包含 FP32/FP64、温度零及 padding 输出不变。torch_xcpu 未新增独立 selector 专项测试文件。

- `gumbel_sample`（中等修改）：Python 包装和底层 Torch schema 在末尾新增 `is_drafting=False`；原调用省略该参数仍走目标流。底层 `gumbel_sample_impl` 签名和 `gumbel_sample_arg_t` 同步新增布尔字段，C++ 调用方、AOT 包装及从核参数结构需要重编适配。draft 在非零温度采样时以 `position+2^30` 构造噪声，目标流保留原算法；counter RNG 抽到 `gumbel_rng.h` 供 sampler/selector 共用。XCPU RNG 仍是原有 counter 混合算法，不承诺与 Triton Philox 逐 token 一致。FP32/BF16 logits、FP32/FP64 噪声路径及 logits cache 契约保留。插件的新 vLLM 采样入口要求显式传入 is_drafting，该要求与 torch_xcpu 的默认参数应区分。既有 CPU 注册入口仍走 MCPU launch，不新增仅供测试的同步计算分支；测试须持有输入 owner 到同步结束。

  - commit `117a6379378b72531a9033299114b5125af1bdd0`：[DFlash2] adapt dflash2 from vLLM v0.28 to support GLM-5.3-DFlash2
  - 接入 commit `188b1a5950a72cf1d5759544a1101a61847bc95b`：[DFlash] adapt XCPU sampling and KV preparation to upstream fixes
  - 测试：`torch_xcpu/test/ops/custom_ops/test_gumbel_sample.py`，新增 draft draw 与显式盐化 target draw 相等、与普通 target draw 分离的 FP32/FP64 检查，并保留 cache/温度/padding 回归；位置推进测试为 `vllm-xcpu-plugin/tests/fake_triton/test_v2_model_state.py`。

### 既有元数据实现修改

- `prepare_dflash_inputs`（小修改）：保留 schema、输出形状和多 KV group 布局。被拒绝的 context 后缀输出 position=0、slot=pad_slot_id；context/query 的 block ID=0 时也输出 pad_slot_id，阻止写入 null block；seq_lens 改为 `min(last_valid_pos+1+num_query_per_req, max_model_len)`。有效输入原契约不变，修改位于既有 `torch_xcpu/include/prepare_dflash_inputs.hpp` 元数据循环，不改独立 torch_xcpu_impl 数值核。各设备移植需同步上述 slot 语义；pad slot 表示跳过 KV 写入。

  - commit `117a6379378b72531a9033299114b5125af1bdd0`：[DFlash2] adapt dflash2 from vLLM v0.28 to support GLM-5.3-DFlash2
  - 测试：`torch_xcpu/test/ops/custom_ops/test_prepare_dflash_inputs.py`，更新多组 reference，新增 rejected_suffix、null_block、max_length 独立边界断言。

补充核对：本区间所有 torch_xcpu_impl 变更归属 selector、新增共享 RNG、Gumbel 参数/实现及版本注册，无 backend 文件变化。`38e7c39aa378b542263e85f71f57d2b8c5cbcdb8` 仅修改 MPI 测试，不改 MoE/AFD schema 或核；对应测试为 `torch_xcpu/test/mpi_custom_ops/test_moe_prepare_fused_v5_finalize_v5_roundtrip_mpi.py`、`torch_xcpu/test/mpi_custom_ops/test_moe_prepare_fused_v6_finalize_v6_roundtrip_mpi.py` 和 `torch_xcpu/test/mpi_custom_ops/test_moe_af_v7_roundtrip_mpi.py`。插件 commit `939a41839140228d5eeed438783a21358b55a852` 取消 v5/v6 缓冲预填，调用方只能按 num_input_rows_valid 消费有效行，容量尾部没有初始化保证。
