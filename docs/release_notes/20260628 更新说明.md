如果需要硬限制思考长度，可以用 vLLM 的 thinking_token_budget 限制 reasoning token。vLLM 文档说明它是请求级 sampling 参数，用来限制 reasoning token 数；未指定时不会额外限制 reasoning，只有普通 max_tokens 约束。

```
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen3.6-35B-A3B",
    "messages": [
      {"role": "user", "content": "直接回答：什么是 MTP speculative decoding？"}
    ],
    "thinking_token_budget": 16,
    "max_tokens": 256
  }'
```

vLLM 最新文档还说明：reasoning_effort="none" 会自动注入 enable_thinking=false；low/medium/high 则会启用 thinking。如果你显式传了 chat_template_kwargs.enable_thinking，显式值优先。不过并非所有模型都支持，此处主要是示例。
```
resp = client.chat.completions.create(
    model="Qwen/Qwen3.6-35B-A3B",
    messages=[
        {"role": "user", "content": "直接给结论：Redis 和 Memcached 的核心区别？ /no_think"}
    ],
    max_tokens=256,
    extra_body={
        "chat_template_kwargs": {"enable_thinking": False},
        "reasoning_effort": "none",
    },
)
```
