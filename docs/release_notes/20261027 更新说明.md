# 20261027 更新说明（20261026 至 20261027）

## 更新重点

- **GLM5.2 FP8 sparse MLA 与 V 上投影融合**：新增 `torch_xcpu::sparse_mla_fp8_vproj`，计算 `output = sparse_mla_fp8(...) @ W_UV`。Decode 调度在一个 mcpu launch 内先后执行 attention 与 V 投影，其余调度仍是两次 launch。插件在 FP8 sparse cache（`fp8_ds_mla`）下默认走该算子，每层少一次 launch。
- **GDN metadata 构建全部下沉到 C++**：Python 侧只解包结果，单次构建的 host 耗时由约 100 µs 降到约 20 µs（x86，提交说明数据）；`qwen_gdn_attention_core_state` 的 host 耗时由约 71 µs 降到约 13 µs（27B spec-decode trace）。
- **MPI all-reduce 原地模式**：新增 `VLLM_XCPU_ALLREDUCE_INPLACE`（默认 0），消除 compile 下 all-reduce 前后的 copy kernel。
- 新增 GLM-5.2-FP8 `dp2tp2ep4` v5 的 eager/compile 预设（FP8 KV cache、alltoallv）。

- 本次 vLLM 没有新提交（HEAD 仍为 `4fd51eab0abcf2fdcbc8b362d7b82b5ddcd29d64`），因此没有 vLLM patch；按约定也没有 vLLM 源码包。torch_mcpu、torch_mpi_ext 同样没有新提交，包内容与 20261026 一致。
- 本次打包没有重新运行算子测试或端到端测试，下文测试路径只说明各提交附带的覆盖。
- `sparse_mla_fp8_vproj` 的 B0 分支目前只是占位（见下文算子变更）。`SparseMlaFp8` 的算子实现版本选择为 B0 时，该算子不会写出 `output`（也不报错）。B0 实现完成前，B0 环境需要设置 `VLLM_XCPU_FUSED_MLA_VPROJ=0`（默认值为 1）。
- `VLLM_XCPU_ALLREDUCE_INPLACE=1` 会把 `inductor_compile_config["enable_auto_functionalized_v2"]` 置为 True（在 `platform.py`）；关闭时 compile 配置不变。

## 各仓库变更说明

### vllm-xcpu-plugin

- **FP8 sparse MLA 融合 V 上投影**（`f8d2a62`）：`XcpuMLASparseImpl` 新增 `forward_mqa_vproj`，在 `kv_cache_dtype == "fp8_ds_mla"` 时调用 `backend.run_vproj`，原先的 `forward_mqa` + `einsum_mhk_hkn_to_mhn(latent, W_UV)` 两步合并。`VLLM_XCPU_FUSED_MLA_VPROJ=0` 保留原来的分离路径用于调试，非 FP8 cache 也走分离路径。测试：`tests/layers/test_mla_rope_kvcache_routing.py`。
- **GDN metadata**（`3378f05`）：`gdn_metadata_patch.py` 改为调用 `torch_xcpu._C.build_gdn_metadata`，Python 只做解包和 dataclass 构造。新增 mixed spec/decode、全 padding、超过 1024 个 conv program 的用例。测试：`tests/plugin_tests/test_gdn_patch.py`。
- **MPI all-reduce 原地模式**（`2cee429`）：`VLLM_XCPU_ALLREDUCE_INPLACE=1`（默认 0）时，`CpuMpiCommunicator.all_reduce` 对输入调用 `all_reduce__wrapper` 并返回输入本身，不再走 `all_reduce_out_wrapper`。同时开启 `enable_auto_functionalized_v2`：V1 会 clone 行 padding 后的 linear 输出 view 再 scatter 回去，每次 all-reduce 多 2 次 copy，V2 直接在 base 上 reinplace。提交说明记录的验证：Qwen3-0.6B/Qwen3.5-0.8B TP2 compile（含 DFlash），all-reduce 前后没有 copy kernel，输出不变。测试：`tests/distributed/test_communicator_collectives.py`。

## torch_xcpu 算子变更

范围：`a38ae1f2cf8da5bcb771f0dcb9b8b4088611c7bc`（不含，20261026 发布）至 `aaaf7362b57c04d1f5df44eb5c3dbf9486b3e07f`（含），共 3 个提交，全部为 dev/0.31 自身提交。

测试用于佐证行为，不代表覆盖了全部 shape、dtype、后端和并行组合。本次打包没有重新运行算子测试或端到端测试。

### 影响 B0 算子实现

- `sparse_mla_fp8_vproj`（新增算子）：Torch schema 为 `sparse_mla_fp8_vproj(Tensor(a!) output, Tensor(b!) latent, Tensor q, Tensor kv_cache, Tensor? logical_topk, Tensor block_table, Tensor query_start_loc, Tensor seq_lens, int max_query_len, int max_seq_len, float softmax_scale, int window_size, bool causal, Tensor tasks, Tensor header_cpu, int bn, Tensor(c!)? partials, Tensor w_uv) -> ()`，即在 `sparse_mla_fp8` 的参数后追加 `latent` 和 `w_uv`。Python 端为 `SparseMlaFp8.run_vproj(...)`，仅 C++ 注册（已加入 `generate_aoti_wrappers.py` 的 `_CPP_ONLY_IMPLS`）。
  - 语义：`sparse_mla_fp8` 的结果先写入 `latent[T,H,512]`（BF16，行连续，head stride 为 64 的倍数；`latent` 由调用方提供，x86 上被物化，NPU 融合 kernel 可以不落盘，但调用方仍需提供），再计算 `output[T,H,N] = latent[T,H,512] @ w_uv[H,512,N]`。`w_uv` 要求连续 BF16 且 `N % 32 == 0`；`output` 可以是 `[T,H,N]`（行连续、行距可大于 `N`）或连续的 `[T,H*N]`。
  - 调度：`sparse_mla_fp8_vproj_impl` 沿用 `sparse_mla_fp8_impl` 的版本分支。A0 与 A1 prefill 先后发出 attention 与 `einsum_mhk_hkn_to_mhn_cpu_impl` 两次 launch；A1 decode（`SparseMlaFp8DecodeKvSplitImpl::execute_impl(args, heads_per_task, vproj)`）在同一个 launch `mcpu::sparse_mla_fp8_decode_kv_split_vproj` 内先执行 kv_split kernel，再调用 `einsum_mhk_hkn_to_mhn_kernel<at::BFloat16>`。
  - B0 需要跟进：**B0 分支目前是占位，没有任何实现**（只有注释，调用后 `output` 不会被写入）。B0 需要实现 `sparse_mla_fp8_decode_kv_split` 加 V 投影的同 launch 版本；源码里记录的进阶目标是在 attention 的 KV 循环期间预取 `W_UV`（decode 时 attention 的访存带宽有空闲），attention 结束后 `latent` 直接驻留片上参与投影，并且要求在完成该优化前保留注释。
  - 另外 `einsum_mhk_hkn_to_mhn_kernel<float|BFloat16>` 被导出到头文件，用于在其他 launch 内复用 A0 kernel 体（`einsum_mhk_hkn_to_mhn` 自身行为不变）。
  - commit `b54f9b1cc0049fd9831f89d92b9ccf3ca4a683ab`：[MLA] add sparse_mla_fp8_vproj: sparse MLA + V up-projection
  - 测试：`torch_xcpu/test/ops/custom_ops/test_sparse_mla_fp8.py::test_sparse_mla_fp8_vproj_matches_separate_ops`（与 `run()` + `einsum` 的结果逐位比较，按 config/case/flat_output 参数化）。

### 不影响 B0 算子实现

- `build_gdn_metadata`（大修改，host 编排，Torch ABI 变化）：新增 pybind 函数 `torch_xcpu._C.build_gdn_metadata(query_start_loc, query_start_loc_cpu, seq_lens, block_table_tensor, num_accepted_tokens, num_decode_draft_tokens_cpu, seq_lens_cpu_upper_bound, is_prefilling, num_spec, num_actual_tokens, block_size_to_align, chunk_size)`，返回 `(tensors, counts, request_rows)`。此前留在 Python 的 first-chunk 分类、uniform spec length、checkpoint 行、core graph-input 槽位也移到 C++。所有输出共用一个设备 buffer 和一个 pinned host buffer，一次构建只有两次分配、一次 H2D copy 和一次 kernel launch。
  - **Torch 底层 ABI 变化**：原有 `torch.ops.torch_xcpu.allocate_gdn_metadata_outputs` 和 `build_gdn_metadata_out` 已删除。直接调用这两个 op 的代码需要改为 `torch_xcpu._C.build_gdn_metadata`；插件的 `gdn_metadata_patch.py` 已同步。返回元组的顺序必须与 `vllm_xcpu_plugin/gdn_metadata_patch.py` 保持一致（头文件已注明）。
  - 无需修改 B0：`torch_xcpu_impl` 下的 `build_gdn_metadata_impl`、`GdnMetadataParams` 未改，kernel launch 的 ABI 不变，变化的只是 host 侧参数准备、buffer 布局和跨 stream 的 `recordStream` 位置。
  - commit `0a8413383e85be25760f16faae37c6e5eab24272`：[GDN] build the whole GDN metadata in one C++ call
  - 测试：torch_xcpu 内没有新增专项测试；覆盖在插件 `tests/plugin_tests/test_gdn_patch.py`（`3378f05`，含 mixed spec/decode、全 padding、超过 1024 个 conv program 的用例）。

- `qwen_gdn_attention_core_state`（小修改，host 开销优化）：packed conv/SSM state view 以及 core 内部的 narrow/squeeze alias 改用 `workspace_view.h` 新增的 helper（`torch_xcpu::narrow_rows` 等）直接构造，绕过 dispatcher。prefill chunk 的 q/k/v/g/beta/out/workspace 改为从一次分配中按 64 字节对齐切分，`empty_like` 改为 `at::empty`。提交说明记录 host 耗时由约 71 µs 降到约 13 µs。
  - Torch schema、`torch_xcpu_impl` 的 kernel 和参数、各 buffer 的 dtype/shape/stride 均未变化，无需修改 B0。`gdn_decode_non_spec_prepared_cpu` 中的 `conv_out` 同样只是把 `at::empty_like` 换成 `at::empty`，shape/dtype 不变。
