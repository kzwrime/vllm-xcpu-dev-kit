# 20261010 更新说明（20261008 至 20261010）

## 更新重点

- EP v5/v6 新增融合 dispatch、专家计算和 finalize 的直接算子接口；插件默认接入，使用按生命周期复用的字节 workspace，减少中间张量独立分配。
- AFD v7/v8 新增 A 端 dispatch/combine 和 F 端 receive/compute/send 融合接口。A 端按实际 SP 分片上报容量，通信域统一协商，F 端使用协商后的容量。
- 修正 EP 与 AFD A 端 workspace 的发送区计算，统一使用 hybrid pack 容量函数；v6/v7 在最大 token 容量大于 128 时额外预留 4 字节空目标计数头。
- 修复 torch.compile 下动态 sequence parallel padding：底层 padding schema 使用 SymInt；vLLM 编译时保留 padding 节点，避免首次 tracing 输入已对齐导致后续动态输入缺少 padding。
- DeepSeekV2/GLM5 模型路径支持通过 VLLM_DISABLE_ATTN_REDUCE_SCATTER_FOR_MOE 关闭 sequence parallel MoE；启动模板同步更新直接分发算子前缀。

以下新增融合接口分别有独立 C++ 文件、声明及 Torch schema，按实际接口分别列项。共有契约：BF16/FP32 activation、TopK 6/8、均匀专家分布，调用方拥有连续一维 uint8、64 字节对齐的 workspace，并使用对应 workspace_size 接口查询容量。EP 的接收行容量 C=P*M，AF F 端 C=A*M，其中 M 是每来源最大 token 数；计算矩阵行容量 R=C*min(T,E)，路由索引仍占 C*T。大块缓冲区只在生命周期不相交时复用，通信 Window 仍由原 transport 管理；新融合接口复用现有从核，并非新增一套 NPU kernel。

- `fused_ep_moe_v5`（新增算子）：按 Backend 注册 `fused_ep_moe_v5_<Backend>` 和 `fused_ep_moe_v5_workspace_size_<Backend>`。一次调用执行 v5 dispatch、两次 GEMM/激活/归并和 finalize，写入独立 `[当前行数,H]` output；显式传入权重、scale/bias、int32 topk_ids/expert_map、FP32 topk_weights、CPU int64 通信元数据及 workspace。发送区最终按 hybrid pack 查询容量，不能用接收区 P*M 行代替；每次提交重新查询 backend scratch，容量不足或 output/workspace 与输入别名时在通信前拒绝。

- `fused_ep_moe_v6`（新增算子）：独立 v6 schema 与 workspace_size 接口，整体输入输出契约同 v5，复用 v6 put 通信。发送区使用 hybrid pack 容量，并在 M>128 时额外保留 int32 空目标计数头，避免 workspace 子视图不足；不得直接复用 v5 的字节数。Python 提供 FakeTensor 注册，执行通过版本化 torch.ops 入口完成。

- `fused_af_a_dispatch_combine_v7`（新增算子）：独立 bf16/fp32 schema，A 端一次提交 dispatch_send 和 combine_recv，显式 output 与 workspace 标记可变，layer_idx 使用 SymInt。路由索引和发送计数保留至 combine 完成，发送区在 dispatch 完成后复用为 FP32 归并区。最终使用共用 hybrid pack 容量函数，M>128 时保留 4 字节空头，并检查 MPI int32 范围；继续使用 v7 put 协议。
