20260917 更新说明（20260913 至 20260917）

更新重点：
- 初步支持在同一个 `MPI_WORLD` 内进行 Attention-FFN Disaggregation（AFD），端到端测试参考 `docs/afd/e2e_test.md`。
	- 新增 Attention 侧 bootstrap/client、MoE expert service、会话协议、远程 fused MoE、权重装载及 MPI world 管理；`torch_xcpu` 新增 AF V7 dispatch/combine 通信算子，并补充多 rank round-trip 测试与启动文档。
- 新增融合算子 `fused_mla_rope_cache`，融合 MLA Q_pe/K_pe RoPE、KV latent 与 K_pe 拼接以及 BF16/FP8 MLA KV cache 写入。
- 新增融合算子 `fused_indexer_k_norm_rope_cache`，融合 indexer K 的 LayerNorm、前 64 维 RoPE、FP8 量化与分页 cache 写入。
- sparse MLA 路径改为在 kernel 内逐 request 根据 `seq_len > topk_tokens` 决定稀疏或稠密访问，支持同一 batch 混合短序列稠密与长序列稀疏请求。
- DSA TopK host metadata 新增元信息：prefill/decode TopK 可接收 CPU `seq_lens`，将 `max_seq_len` 下传给算子实现用于后端 kernel 选择。
- 修正 GLM-5/5.2 路由 dtype 与 FP8 MoE block quant 的 TP size 获取，避免 compiled graph 中多余的 dtype fallback，并使用当前 MoE 配置的 TP size。
- 开发套件新增 AFD 启动配置及说明，扩展 4K/多请求长上下文测试入口，并移除 `sglang-humanize-review` skill 及其 review corpus。

备注：
- `seq_lens_cpu` 只提供 host 侧保守的 `max_seq_len` 调度提示；每行有效范围仍以 device 侧 starts/ends/lengths 为准。
- 无需再适配 `indexer_k_quant_and_cache`
- GLM 建议测试项
	- `--long-context-4k-test` 运行冻结 4K 长上下文 QA，打印回复并判断答案是否正确
    - `--long-context-multi-test` 并发测试 0.5K、4K、8K 长上下文 QA，并打印和判断全部回复

## `torch_xcpu` 算子变更

统计范围为 2026-09-13（不含）至 `718253c7979d3471ee05053bb4b40d5a5dedad20`（含）。以下测试用于佐证所述行为，不代表覆盖全部 shape、dtype、后端和并行组合。

- `fused_indexer_k_norm_rope_cache`（新增算子）：新增原地写 cache 的融合接口，对 row-strided BF16 `K[T,128]` 依次执行 FP32 affine LayerNorm、前 64 维 RoPE、FP8 E4M3 量化和分页 cache 写入；支持 GPT-J/NeoX RoPE 布局、BF16/FP32 `cos_sin`、FP32/UE8M0 scale、少于 padded K 行数的 slots，并跳过负 slot。算子团队需接入该融合算子的完整 ABI 与数据布局；独立的 `indexer_k_quant_and_cache` 无需作为主路径重复接入。
	- commit `a4b8dca1850562c0d157d8e872f64d57a3610113`：[DSA] impl fused_indexer_k_norm_rope_cache
	- 测试：`torch_xcpu/test/deepseek_v32/test_indexer_fused_k.py`
- `fused_mla_rope_cache`（新增算子）：新增原地修改 `q_pe`、`k_pe` 并写 MLA KV cache 的融合接口；输入为 BF16 `q_pe[T,H,64]`、`k_pe[T,64]`、`kv_c[T,512]`，支持 GPT-J/NeoX RoPE、BF16/FP32 cos/sin、负 slot 跳过及 padded decode。`kv_cache_dtype=auto` 写 BF16 576-element entry；`fp8_ds_mla` 写 uint8 656-byte entry，并对 512 维 latent 按 128 元素分组生成 FP32 scale。
	- commit `6fc389ced23a873560399542d4c89f604edf60df`：[DSA] impl fused_mla_rope_kvcache_update to fuse Q_pe RoPE + K_pe RoPE + concat(KV latent, K_pe) + write MLA KV Cache
	- 测试：`torch_xcpu/test/deepseek_v32/test_fused_mla_rope_cache.py`
- `top_k_per_row_prefill`（小修改）：Python 包装和底层 Torch schema 新增末尾可选参数 `Tensor? seq_lens_cpu=None`，要求为连续 CPU int32 `[num_requests]`；dispatcher 在 host 侧计算 `max_seq_len` 并下传实现层供 kernel 选择，未提供时使用 `-1`，TopK 输出语义不变。
	- commit `d92aa8eedf86373a399f3fb7787b528a98ff07fe`：[DSA] support max_seq_len for top_k_per_row_prefill and top_k_per_row_decode
	- 测试：`torch_xcpu/test/deepseek_v32/test_indexer_topk.py`（覆盖有/无 `seq_lens_cpu` 的 fullgraph 调用）
- `top_k_per_row_decode`（小修改）：与 prefill 接口一致，新增末尾可选 `Tensor? seq_lens_cpu=None`，由 host 求最大序列长度并传入实现层；旧调用因默认值保持兼容，device `lengths` 仍决定每行实际有效区间。
	- commit `d92aa8eedf86373a399f3fb7787b528a98ff07fe`：[DSA] support max_seq_len for top_k_per_row_prefill and top_k_per_row_decode
	- 未新增直接覆盖 decode `seq_lens_cpu` 参数的专项测试；现有基础行为测试位于 `torch_xcpu/test/deepseek_v32/test_indexer_topk.py`
- `sparse_mla_fp8`（中等修改）：传入 sparse TopK metadata 只表示算子具备稀疏能力；各 request 在 kernel 内按 `seq_len > topk_tokens` 独立选择稀疏 TopK 或稠密 causal/window 遍历，使同一 batch 中的短序列不再被错误强制走稀疏路径。Torch schema 不变，BF16、FP8 DS-MLA 及 DeepSeek V3.2 sparse MLA 实现同步更新。
	- commit `718253c7979d3471ee05053bb4b40d5a5dedad20`：[DSA] parse dense/sparse according to seq_len inside kernel instead of in python
	- 测试：`torch_xcpu/test/ops/custom_ops/test_unified_attention_sparse_mla.py`（新增 mixed dense/sparse threshold case）
