# 20260930 更新说明（20260926 至 20260930）

## 更新重点

- GDN 元数据构建迁移到 C++：CPU 侧完成请求分类和 chunk/卷积调度元数据准备，设备侧通过单次 launch 生成状态索引、token 分区和初始状态标记；插件替换 `GDNAttentionMetadataBuilder.build`，保留非 XCPU 与 cutedsl 回退。理论上来说 Qwen3.8 DFlash2 的 Host 开销会大大降低。
- DSA 新增 C++ SparseAttnIndexer 主流程，按原有顺序调用 cache、gather、logits、TopK 和 pack/unpack 算子。插件通过 OOT CustomOp 接入，eager/compile 共用运行期元数据句柄，减少该主流程的 Python fallback。同时降低编译时间到约 20 分钟。
- MLA 启动 profile 仅在 `prefill_backend is not None` 时模拟 dense prefill 的展开上下文，避免没有该后端时的额外大 tensor 分配，降低该路径启动峰值内存。
- AFD V7 新增 A/F 双侧 compile：A 允许普通 compile 并继续拒绝 CUDAGraph；F 通过 `--compile` 编译每层 receive/compute/send 事务，SymInt layer index 复用跨层图，ORDERED effect 保留无输出发送。开发套件提供八组 eager/compile preset、跨机矩阵 `--mode compile` 和验证文档。
- MoE v5/v6 的 prepare/finalize 共享同一 packed-record 通信窗口，减少独立窗口占用；v5 finalize 改为固定 rank 槽并直接按返回行索引归约，从核参数结构需同步更新。
- DSA 的 Q RoPE 固定 rotary_dim=64，将模板配置从 5376 收敛到 84；纯 decode 在完整覆盖 TopK buffer 时跳过预清零。插件同步更新 sparse indexer 上游源码兼容性 hash。

## torch_xcpu 算子变更

### 从核相关修改

- `moe_finalize_v5`（中等修改）：接收结果从紧凑回传布局改为每 rank 固定 `max_num_input_rows * hidden_dim` 元素槽，复用 prepare 的 packed-record 窗口前缀；Alltoallv 的 rdispls 固定为 rank*slot_elements。reduce 直接按 `return_row_indices * hidden_dim` 读取，移除 compact 位移转换和相应 rdispls DMA，`MoeFinalizeV5ReduceArgs`/state 删除 rdispls、max_num_input_rows 和 ep_size 等字段。从核参数结构须同步更新；Torch schema 不变，return_row_indices 保持固定槽索引且不被修改。总容量的 MPI int 检查按共享 packed 窗口计算。

### 从核无关修改

下列更新/修改都不涉及从核计算逻辑，如果没有冲突理论上可以不用处理。

- `build_gdn_metadata`（新增算子）：新增 `GdnMetadataParams` 和 `build_gdn_metadata_impl`，Torch ABI 为 `build_gdn_metadata_out(..., Tensor(a!)?[] outputs) -> ()`。配套 `allocate_gdn_metadata_outputs` 每次构建分配独立的 22 项可选输出，末项为 CPU int64 `[7]` 计数及有效位掩码；调用方须保持固定输出顺序，out 入口不返回别名。设备输入包括 int32 `[B+1]` query offsets、`[B]` seq_lens 和二维 block table，并按实际输入 stride 读数据；CPU query offsets 为 int32，draft counts 支持 CPU int32/int64。CPU 同步完成分类、chunk 和卷积元数据准备，A0 单次 launch 完成状态 gather、初始状态判断及 spec/non-spec token 分区；纯 spec token 索引为 int32，混合分区为 int64。支持空请求、非预测/预测 decode、混合 prefill 和 align 状态索引；跨流使用记录 allocator stream，避免异步任务尚未完成时存储被复用。NPU 接入须实现新增参数结构和 launch，版本选择使用 `TORCH_XCPU_GDN_METADATA_IMPL`，B0 尚未实现。

- `sparse_attn_indexer`（新增算子）：新增 C++ 编排入口，原地更新 cache 和 int32 TopK buffer，按 cache 插入/可选清零、prefill chunk gather/logits/TopK、decode pack/logits/TopK/unpack 的顺序调用既有实现，不新增或修改从核数学计算。Q 为 BF16 `[T,H,128]`，weights 为 FP32 `[T,H]`，cache 为 uint8 `[P,64或128,132]`，支持页间 padding；decode context lengths 为连续 int32 `[B,NEXT_N]`，NEXT_N 为 1 至 10。调用方预分配并传入 K values/scales、logits、padding Q/weights/TopK 六组 workspace，logits 的 prefill 行/列分别按 8/512 对齐，decode 列按 256 对齐；容量不足明确报错。空 prefill chunk 输出 -1，`skip_kv_gather` 复用先前 chunk 的 K；K 插入和 TopK 预清零由独立标志控制。最新实现对存在 decode 元数据、无 prefill chunk、无需 padding 且 `num_decode_tokens == num_tokens` 的纯 decode 跳过预清零，由 decode TopK 完整写入，包括短行/空上下文的 -1；prefill、padding 和未完全覆盖的行保留初始化。插件限制 PCP=DCP=1、禁用 FP4 Q/cache 和 DBO/ubatching，模型的 MXFP4 权重量化不受 FP4 cache 限制。
