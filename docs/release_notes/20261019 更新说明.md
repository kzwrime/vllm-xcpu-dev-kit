# 20261019 更新说明（20261013 至 20261019）

## 更新重点

- `fused_ep_moe_v5` 大幅度更新。算子需配套更新
  - 支持 shared expert 和 dispatch-alltoallv 延迟隐藏，需要 mpi 支持异步通信
  - 支持 shared expert 和 route expert 计算的未处理融合（ scale gated add 之类的 ）
  - 更新 moe_grouped_gemm_with_index，文档见 `torch_xcpu/docs/ops/moe_grouped_gemm_with_index.md`
  - 更新了 pack/permute(route)/local_reduce 算子
  - 减少了 host 开销
- 减少了 indexer 部分的预留内存，需要恰当设置 `USER_VLLM_MAX_NUM_SEQS` 为较小的值，
- 通过 torch.compile 内存池优化让 indexer 和 moe 的内存可以复用

建议设置
- 请务必注意查看并更新 `user_env`
- GLM5.2 时，建议设置 `USER_VLLM_MAX_NUM_SEQS` 为 设置为 1~4
- EP64 时，建议把 `VLLM_XCPU_MOE_MAX_RECV_TOKENS` 设为 `USER_VLLM_MAX_NUM_BATCHED_TOKENS / TP / 8`

---

- `fused_ep_moe_v5` 整体重写：每个 EP rank 使用固定大小的消息区（region），dispatch 与 combine 各一块进程级 MPI 窗口，不再每次调用创建窗口；dispatch/combine 任务内不再有逐 rank 循环，计数由新增的内部 kernel `moe_ep_v5_pack`、`moe_ep_v5_route`、`moe_ep_v5_local_reduce` 写出，位移为常量。GEMM1 改用新增算子 `moe_grouped_gemm_with_index` 直接读取接收窗口，不再有 permute/unpermute/独立 silu。v5 的线协议、窗口和 workspace 与 20261013 版本不兼容，workspace 必须重新查询；所有 EP rank 须在首次调用前执行新增的集体调用 `fused_ep_moe_v5_initialize_windows`（插件在层初始化时完成）。插件同步接受所有者范围内任意单射的 expert map 重编号/过滤。
- `moe_grouped_gemm_with_index` 改为对每个专家各执行一次 gather、GEMM 和 silu_and_mul（不再按 256 行分块），临时缓冲区按本次调用中最大专家的行数分配；`input_indices` 只接受 int32，int64 会被拒绝，调用方需同步修改。gather 被拆成新增的可版本化内部 kernel `indexed_gather`（`TORCH_XCPU_INDEXED_GATHER_IMPL`，A0 为参考实现，B0 为留给算子团队的空占位）。
- v5 支持把 SP 复制的 shared expert MLP 融合进融合算子：在 round 0 的 dispatch 之后、route 之前计算 shared MLP，gate、缩放与 routed 结果的合并在最终归并 kernel 内完成；shared MLP 沿用其已打包的 FP8/MXFP4/未量化 linear 权重，不走 grouped GEMM。插件新增 `VLLM_XCPU_FUSE_SHARED_EXPERTS`（默认 1，设为 0 关闭）；`TORCH_XCPU_FUSED_EP_MOE_V5_ASYNC_DISPATCH=1`（默认关）可让 round 0 的 dispatch 与 shared MLP 重叠。非 v5 后端及不满足条件的层保持原有未融合路径。
- Inductor 中间 buffer 内存池默认开启：`vllm_scripts/user_env_template.sh` 中 `TORCHINDUCTOR_MEMORY_PLANNING` 默认改为 1（设为 0 关闭），`TORCHINDUCTOR_MEMORY_POOL` 默认 `intermediates`，`AOTI_TORCH_ALWAYS_REUSE` 默认随之为 0（关闭规划时为 1）。插件把生效的 `memory_planning`/`memory_pool` 写入编译配置及缓存 key（模型自带的编译器选项优先），并在 V2 model runner + `DYNAMO_TRACE_ONCE` + inductor 且开启内存规划与 `intermediates` 内存池时，于正常 trace 之后释放空闲 warmup buffer、再以 `max_num_batched_tokens` 预热最大形状。配套地，torch_xcpu 的融合 EP/AF 算子的输入、输出与 workspace 别名检查由“共享 storage 即拒绝”改为“字节区间重叠才拒绝”，避免内存池把互不重叠的 buffer 切自同一 storage 时被误拒。
- `TORCHINDUCTOR_DIRECT_DISPATCH_PREFIXES` 默认改为 `torch_xcpu,torch_mpi_ext`（此前为 `torch_xcpu,torch_mpi_ext.all_reduce__wrapper`，即由 `torch_mpi_ext` 前缀覆盖 `all_reduce_out_wrapper` 等其他入口）。
- `DYNAMO_TRACE_ONCE` 模式下，worker 在上游 warmup 之前，在所有 rank 上以 `max_num_batched_tokens` 先 trace 一次模型图；此前 DP 下空闲 rank 先 trace 单 token 的 dummy batch，Dynamo 会特化 T=1，之后该 rank 的所有 batch 都走 T=1 图。
- DSA：插件 patch `mla.indexer.get_max_prefill_buffer_size`，取上游值与 `max_num_seqs * max_model_len` 的较小者，用于 prefill K buffer 和 indexer 元数据的分块上限。
- torch_mcpu 新增 `aten::minimum` 与 `aten::minimum.out`，支持 0 维 CPU 标量操作数、dtype 提升，复数输入报错。
- vLLM 自 20261013 发布（`5cc699cf3320032f178c4efbb7b06a13668eb843`）以来无新提交，本次不提供 vLLM 源码包，也没有新的 vLLM patch。

## torch_xcpu 算子变更

统计范围为上一版基线 `2283e815dad22ced19919ceaf0ac5d133261fb2b`（不含，2026-10-13 发布快照）至 `7de3bc0a50582d33cd255da211e759fcbe6598f8`（含，2026-10-19 发布快照），按 Git 提交拓扑统计，共 7 个提交。本次未另行指定交付后区间或排除模块。测试用于佐证行为，但不代表覆盖全部 shape、dtype、后端和并行组合；本次文档打包未重新运行算子或端到端测试。

下文记 P 为 EP rank 数、E 为每 rank 专家数（`local_experts`）、K 为 TopK、H 为 hidden size、M 为 SP 后每 rank 输入上限、C 为每（源，目的）每轮记录配额（未分块时 C=M，否则 C=min(M,Q)）、B=H×sizeof(T)、S 为单个 rank 消息区（region）字节数。`fused_ep_moe_v5` 的线协议、窗口和 workspace 已整体重写，不与 20261013 版本兼容；详见 `torch_xcpu/docs/moe_ep_v5.md` 与 `torch_xcpu_impl/include/moe_ep/v5_protocol.h`。

### 涉及算子 impl 级修改

本节按提交到 MCPU stream 的独立任务实现是否改变分类，包含计算、通信和控制任务。条目涉及的 schema、包装及 workspace 配套变化一并保留；不以文件是否位于 torch_xcpu_impl 目录作为唯一依据。

- `moe_grouped_gemm_with_index`（新增算子）：独立于 EP/MPI 的索引输入 grouped GEMM，按专家分组的输入索引直接读取原始输入、连续写出结果，可选融合 SiLU-and-mul epilogue。每个 `moe_grouped_gemm` 后端有一一对应的 `<Backend>WithIndex`，共 13 个（AccBf16、PortableBf16、TorchBf16、AccFp32、IntelAmxFp8、PortableFp8Direct、PortableFp8Lut、AccFp8、IntelAmxMxfp4、PortableMxfp4Lut、AccMxfp4、PaddingExampleFp8、PaddingExampleMxfp4），权重 prepack 物理布局与同名 grouped 后端逐字节相同，两者可互用。每个后端注册五个 `torch.ops.torch_xcpu` 入口：`moe_grouped_gemm_with_index_prepare_<Backend>`、`..._packed_weight_storage_bytes_<Backend>`、`..._prepack_weight_<Backend>_out`、`..._prepack_scale_<Backend>_out`、`scaled_moe_grouped_gemm_with_index_<Backend>_out`。执行 schema 为 `(Tensor(a!) output, Tensor input, Tensor input_indices, Tensor packed_weight, Tensor? weight_scale, Tensor? bias, Tensor expert_offsets, int valid_rows, int scale_block_n, int scale_block_k, int input_row_stride_bytes, int input_offset_bytes, int epilogue, Tensor(b!) scratch, int index_expert_stride=0) -> ()`；Python 侧新增 `initialize_moe_grouped_gemm_with_index`、`MoeGroupedGemmWithIndex`、`MoeGemmEpilogue`（NONE=0、SILU_AND_MUL=1）、`MoeIndexedBackend`、`MoeIndexedWeightFormat` 等并导出到 `torch_xcpu.ops`，`valid_rows` 为 host int，`input_indices` 只接受 int32（C++ 检查和 FakeTensor 均拒绝 int64 与浮点）。契约：
  - 路由 r 读取 `input.data_ptr() + input_offset_bytes + input_indices[i(r)] * input_row_stride_bytes` 起的 K 个连续激活元素（BF16，FP32 后端为 FP32）；`input_indices` 为连续 int32，允许重复，只读前 L 个，不接受 -1 sentinel；输出按 expert-major 顺序只写前 L 行，容量尾部保持原值。三种输入布局（带行 padding 的矩阵、固定头部记录、字节偏移 + stride=1）共用同一公式，偏移相对 `data_ptr()` 而非 storage 起点。
  - `expert_offsets` 为连续 int32 `[E+1]`，首项 0、单调不减、末项 L。`index_expert_stride=0` 时 `input_indices` 为 `[R]`，i(r)=r；`>0` 时为 `[E*index_expert_stride]`，专家 e 的第 j 行索引位于 `e*stride+j`，且该专家路由数不得超过 stride（kernel 内检查）。输出始终稠密 expert-major，不受 stride 影响。
  - `epilogue=SILU_AND_MUL` 时输出宽度 N/2（N 为偶数），GEMM 结果先舍入到输出 dtype 再经独立 `silu_and_mul` kernel，等价于「grouped GEMM（BF16 结果）→ silu_and_mul」；NONE 与同名 grouped GEMM 逐位相同。输出 dtype 与激活相同（FP32 后端为 FP32，其余 BF16）。
  - 示例实现对每个非空专家各执行一次 gather → 稠密 GEMM → silu_and_mul：gather 由 `IndexedGemmInput::gather` 指向的 `indexed_gather` kernel 把该专家的 A 行取成稠密 `[m,K]` 缓冲区，复用 grouped 后端的稠密 linear kernel，再单独做 silu_and_mul（每个后端源码中有 `TODO(acc)`）；不再按 256 行分块，缓冲区按本次调用中最大专家的行数分配（所有专家为空时不分配），临时内存因此随最大专家的行数增长。NPU 实现应把 gather 融合进 GEMM 的 A 行读取、把 silu_and_mul 融合进输出写回，不应沿用该缓冲区。gather 缓冲区和 silu 结果缓冲区是 kernel 内部临时分配，`scratch` 只放后端自己的临时区（目前只有 Intel AMX 的每线程 B/C 临时区，其余为 0），大小由 prepare 查询。
  - Tensor 接口只检查 shape、dtype、device、stride、scratch 容量、host L 和存储别名（输出、scratch 不能与输入、权重、scale、bias、路由元数据共享 storage），不拷贝索引到 host、不扫描索引内容；索引越界由数据生产者保证。内部 C++ pipeline 可使用 `DeferredGemmInput`/`IndexedGemmRowCount` 传入异步产生的输入基址和有效行数。
  - 新增算子实现版本项 `moe_grouped_gemm_with_index`（环境变量 `TORCH_XCPU_MOE_GROUPED_GEMM_WITH_INDEX_IMPL`，当前仅 A0）；gather 的实现版本项见下文 `indexed_gather`。`silu_and_mul` 本次无行为修改。
