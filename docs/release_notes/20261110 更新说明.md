# 20261110 更新说明（20261105 至 20261110）

注意！

- **`fused_ep_moe_v5` 的分块通信协议变更（`torch_xcpu` `a03790a`）**：「无发送」语义收紧为「无记录且无下一轮」：分块轮不再给没有记录的目的 rank 发 header，只有自身还有下一轮的 source 才向全部 peer 发 header-only keepalive。旧版本的 route 会把 chunked 轮缺失 header 当作错误，**新旧版本的 rank 不能混部，各 rank 的 torch_xcpu 必须一起升级**。
- **插件的 MLA 融合开关重构为 0/1 布尔（`070e94e`）**：`VLLM_XCPU_COMPILE_PASS_DEEPSEEK_V32_FUSED_MLA_QNORM_QB_UK_ROPE_CACHE` 与 `VLLM_XCPU_COMPILE_PASS_DEEPSEEK_V32_FUSED_MLA_ADD_NORM_QKVA_QNORM_QB_UK_ROPE_CACHE` 只接受 `0`（默认，不融合）/`1`（应用 pass）；20261105 的版本字母取值不再被解析。20261105 引入的 eager 路径开关 `VLLM_XCPU_FUSED_MLA_QNORM_QB_UK` 已删除（`cdb76e1`），compile pass 是融合的唯一入口，eager 一律走未融合基线。需要指定实现档位时直接设置 torch_xcpu 的 `TORCH_XCPU_FUSED_MLA_QNORM_QB_UK_ROPE_CACHE_IMPL` / `TORCH_XCPU_FUSED_MLA_ADD_NORM_QKVA_QNORM_QB_UK_ROPE_CACHE_IMPL`（默认最高档）。
- vLLM 与插件需配套升级：`vllm` `065cbdb` 修改了 `deepseek_v2.py`（EAGLE3 aux 捕获），插件 `2eb1cb8` 同步了 upstream 兼容 hash，旧插件配新 vLLM（或反之）会触发兼容性检查失败。vLLM `d5dc410` 的 BF16 linear 打包建立在 torch_xcpu 20261105 交付的 BF16 后端族之上，vLLM 升级时 torch_xcpu 不应低于 20261105。

## 更新重点

- **修复 GLM-5.2 EAGLE3 aux hidden states 捕获（14 层周期性空隙的根因）**：`vllm` `065cbdb`。模型循环原本在 6 个 EAGLE3 aux 层（和最后一层）额外做一次 out-of-place 的 `hidden_states + residual` 加法，这个和恰是 `fused_add_rms_norm` 内部计算的 pre-norm sum；现在 decoder layer 在 `capture_input_sum` 时直接返回 norm 的 residual 输出，消除了每 14 层一次、在 mcpu stream 上表现为空隙的 `aten::empty([T,6144])` 与加法。eager 下 norm 分发到把和写回调用方 residual 缓冲的 inplace 实现，会被同层的 `post_attention_layernorm` 覆盖，为此新增 `IrOp.functional()` 把 aux 捕获限定到 functional 实现。验证（GLM-5.2-MXFP4 dp2_tp2_ep dflash2_5）：aux 位置 stream 空隙从 8/8 step 降到 0/11 step，无 period-14 事件。dev-kit `de7ba0e` 的 `docs/glm52-dflash-14-layer-mcpu-gap-v0.31.md` 与 `diag/mcpu_trace/test_aux_sum_capture.py` 记录了定位与验证过程。
- **未量化 BF16 linear 交给 torch_xcpu 打包后端**：`vllm` `d5dc410` + 插件 `b9bd2da`。`VLLM_USE_XCPU_LINEAR` 开启且平台为 mcpu 时，`dispatch_xcpu_bf16_linear()` 在 `process_weights_after_loading` 里用 torch_xcpu 的 BF16 后端 prepack 权重，按 `skip_bias_add` / RowParallel-rank 语义烘焙 FP32 bias，释放原始权重，`default_unquantized_gemm()` 运行 packed handle；router gate 通过 `out_dtype` 保持 FP32 logits（插件侧优先走 `layer._xcpu_bf16_linear`）。DFlash/Laguna 的 fused-KV 堆叠在缓冲建好前保留原始 qkv 权重；lm_head（`UnquantizedLinearMethod` 豁免场景）为 logits/共享 embedding 保留原始权重；纯 FP32/FP16 与不支持形状仍走 `torch_xcpu.ops.linear`。
- **Inductor post-grad pattern pass：MLA 前半段/整层融合进 compile 图**：插件 `9606ca0`（phase-1 qnorm_qb_uk pass，安装为 Inductor 的 `post_grad_custom_post_pass`）、`cdb76e1`（模块/env 全名化，删除 eager 前端路径）、`7d3b7be`（phase-2：input add-norm + fused_qkv_a + MLA 前半段合为 `fused_mla_add_norm_qkva_qnorm_qb_uk_rope_cache`，两个 pass 共享 `_front_window.py`）、`2788406`（phase-3：把 SP all-gather 吸收进融合算子，`ag_comm` schema 由 int 改为 `Tensor?`，placeholder 保持 MPI handle 为运行期值，compiled 产物跨进程可复用）、`070e94e`（开关收敛为 0/1）、`7255caa`（带 sparse indexer 的整层经 `fused_mla_add_norm_qkva_wk_wq_qnorm_qb_uk_rope_cache` 融合，后端匹配从图中实际 overload 读 fp8/bf16 backend 值，逐层用 `supported()` 门控）。`vllm` `975b7f0` 把两个 pass 开关登记进 envs 并纳入 compile factors，改开关不再命中旧 compile 缓存。E2E（DP2×TP4×EP8，冷缓存）：8/8 rank 报「fused 7」，每 rank 吸收 3/4 个 SP gather，输出与未融合基线 token 一致。
- **mega-kernel 算子族扩展与整层算子**（按发布约定，详见「torch_xcpu 算子变更」一节开头的排除说明）：`1bbf3ff` 把 `fused_mla_add_norm_qkva_qnorm_qb_uk_rope_cache` 集成为 Torch 算子（GLM-5.2 层前部一体：in-place input_layernorm + FP8 fused_qkv_a + 原 MLA 前半段，任意 token 数走同一算子；可选融合 all-gather，构建宏 `TORCH_XCPU_FUSED_MLA_ADD_NORM_QKVA_FUSE_ALL_GATHER` 默认 0）；`3ab76d8` 新增带 sparse indexer 的整层算子 `fused_mla_add_norm_qkva_wk_wq_qnorm_qb_uk_rope_cache`（A0 未融合 / A1 段程序 / B0 占位）；`e87aedc` 把实现阶梯重编号为 A0 = 未融合基线；`6629750` 两个融合算子默认取最高档（A3/A2）；`ecf1e29` 把 PE-team 探测从 mk 移入 `operator_version`（import 时一次性探测，A0 进程不探测）；`6e32867` 新增 add_norm_qkva 段程序 v1/v2、`FusedAddRmsNorm` 黑盒、`wait_host_flag`、matrix DMA 与 `Gemm::LoadABcast`；`2cce46c`/`290f3e8`/`c6a0b66` 演进 Gemm Scratch、`ComputeRows`、DMA 广播集体语义与 RMA sub-die 局部编号；`46bc0f7` 段程序删除 `IsNeox`、RoPE 固定 interleaved（独立 rope 算子与 torch ABI 的 `is_neox` 不变）；`56a0e2f` 把 wk 重分为 10 PE × 16 列的 half block（`WeightNBlocked{Vnni,KMajor}Half<32>` / `WeightAccBf16Half` 直接视图 BN=32 的后端 prepack，无 repack/schema/vLLM 变化，NPU 骨架换成 `bf16_acc_16x16x1024`），并统一 wq 的 chunk-2 发出时机。
- **fused_ep_moe_v5 分块协议简化**：`torch_xcpu` `a03790a`，见开头「注意」。decode、空闲 DP 组和 dummy run 不再为每个 peer 支付 header 发送；多轮 prefill 保持 full-chunk 轮 + 稀疏末轮。E2E（Qwen3-30B-A3B DP2×TP2×EP4，C=64）：每个 prefill 层 full-chunk + sparse final，decode 单稀疏轮，空闲 DP rank 完全静默。配套工具：插件 `e72fb45`（`XCPU_EP_PROBE_LOG` 输出每轮 sendcounts）、dev-kit `e7c5842`（`analyze_ep_probe.py` 轮形分析器 + `Qwen3-30B-A3B_dp2_tp2_ep_eager_alltoallv_v5_epchunk64.sh` 预设）。
- **torch_mcpu 显式 `clamp_min`**：`9f17a40` 在 PrivateUse1 上注册 `clamp_min`、`clamp_min_`、`clamp_min.out`（Scalar）与 `clamp_min.Tensor`、`clamp_min_.Tensor`、`clamp_min.Tensor_out`（Tensor），host 侧推断 shape/dtype、预分配输出，异步 kernel 只捕获裸指针与元数据；complex dtype、out shape 不匹配、不安全 inplace 转换在 launch 前拒绝。

### 影响 B0 算子实现

- `fused_ep_moe_v5`（中等修改，v5 pack/route 分块通信协议）：分块轮的发送规则从「每个目的 rank 至少收到 header」改为「当且仅当该目的 rank 本轮有记录、或本 source 还有下一轮才发送」；仍有下一轮的 source 向全部 peer 写 header-only keepalive（N=0），使所有 rank 对下一轮的判定（全部 source 的 has_next_round 之 OR）保持一致；无记录且无下一轮时发送 0 字节，与未分块调用一致。
  - **B0 需要跟进的契约变化**：`MoeEpV5PackArgs`（`torch_xcpu_impl/include/moe_ep/v5_pack.h`）的 `bool always_send_header` 更名为 `bool chunked`，语义如上；pack 侧 `send_bytes = message_bytes(rows)` 仅当 `rows > 0`，keepalive 循环把零记录目的提升为 `message_bytes(0)`；route（`src/moe_ep/v5_route.cpp`）在 chunked 模式下缺失 header 不再是错误，走 absent-source 路径（rows=0 / 空 expert counts）。接收窗口语义不变（`kMoeEpV5NoMessage = -1`、窗口 0xFF 初始化、route 消费后 retire header）。`moe_ep_v5_pack` / route 是 MCPU launch（A0 当前实现，B0 槽位已预留），**实现 v5 的 B0 必须按新规则收发，且不得与旧版本 rank 混部**（旧 route 把缺失 header 当错误）。
  - 效果（提交说明）：decode、空闲 DP 组与 dummy run 不再为每个 peer 支付 header 发送；多轮 prefill 保持 full-chunk 轮 + 稀疏末轮。
