# 20261005 更新说明（20261001 至 20261005）

## 更新重点

- 修复 Mamba align 推测解码的跨层状态一致性：vLLM V2 保存完整请求槽的 accepted-token 只读快照，kernel 写独立输出，避免第 0 层重置计数后其他层使用不同的 checkpoint 位置。
- 修复 Mamba chunked prefill 的状态块回收：回收区间跨过 null gap，保留仍有效的 checkpoint 和在途状态，请求释放后清理回收进度。新增长提示、重复回收及请求 ID 复用回归，避免旧状态块随 prefill chunk 累积。
- Linear 输出底层 storage 行容量按 16 对齐，Python 返回有效逻辑行；
- Sparse MLA FP8 metadata 的 CPU task 缓冲从 zeros 改为 empty，仅异步拷贝有效任务 section；空 step 不拷贝，device 容量尾部没有零初始化保证。
- Compile 支持 `aten.sym_storage_offset` metadata lowering，保留中间 view 的 storage offset；vLLM 编译因子忽略 DP rank/local rank 和 RPC ready 基础端口，减少由这些变量差异造成的缓存分裂。Qwen3.8-27B-FP8 的 DFlash2 compile 预设修正为 TP2。

## torch_xcpu 算子变更

### 重要修改，必须跟进

修改了 SparseMlaFp8 的 Metadata Builder 部分，减少了 Decode 时的 host 开销，必须同步修改所有 SparseMlaFp8 后端 ！！

- `SparseMlaFp8`（中等修改，既有 backend 的 build_metadata）：base、decode KV split、prefill、prefill AMX 四条路径仍每次分配独立、固定容量的 CPU tasks，但使用 empty，完整写有效 task 后只异步拷贝对应 section 的有效行；新增 task_count 一致性检查，空 step 不提交拷贝。header、task 字段布局和计算接口未变，device 未使用行保留原内容，不能假设其为零；计算只能消费 header 指定范围。CPU 切片须持有完整 storage 至异步拷贝完成，禁止提前覆盖或复用源。NPU 元数据和拷贝接入需遵守同样的有效范围及生命周期契约。

### 输出容量和空输入契约，合并无冲突可以接受

- `mm`（小修改）：`mm_out` 接受连续输出 `[M_out,N]`，其中 `M_out>=M`、输入为 `[M,K]` 和 `[K,N]`；C++ 显式校验二维、同 dtype/设备及列维度。fallback 的 CPU view 只暴露前 M 行，防止 resize 或写容量尾部；M=0 提前返回。底层 Torch schema 未变，移植实现需支持物理容量与逻辑行数分离；普通 `mm` 未传 out 时仍按逻辑尺寸分配。

  - commit `91f9b07a82008748c8badc3b6318da4b2f252193`：[Ops] align number of physical rows of the output tensor of gemm to 16
  - 测试：既有 `torch_xcpu/test/ops/gemm_ops/test_ops_mm.py`；未新增对应的超额输出容量或零行专项测试。

- `addmm_v2`（小修改）：复用上述输出容量检查，原地将矩阵乘积加到有效行的现有 out addend；fallback 的 addend 和 destination 均限定前 M 行，不读写尾部，M=0 提前返回。schema 未变，调用方须预先初始化有效行的 addend。

  - commit `91f9b07a82008748c8badc3b6318da4b2f252193`：[Ops] align number of physical rows of the output tensor of gemm to 16
  - 测试：既有 `torch_xcpu/test/ops/gemm_ops/test_ops_mm.py` 的 bias/fallback 回归；未新增对应的超额容量、尾部不变专项测试。

- `linear_prepacked`（小修改）：BF16 Python 包装分配 `ceil(M/16)*16` 行，再返回前 M 行并还原逻辑 shape；底层 `linear_prepacked_out` 将输出行约束从等于 M 放宽为不小于 M，M=0 不 launch。schema、权重 packing 和数值核未变，从核按输入 M 计算，不能把 out 容量当作计算行数。

  - commit `91f9b07a82008748c8badc3b6318da4b2f252193`：[Ops] align number of physical rows of the output tensor of gemm to 16
  - 测试：未新增对应的 16 行 storage 对齐、超额 out 或零行专项测试。
