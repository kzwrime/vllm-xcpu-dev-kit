# 20261013 更新说明（20261010 至 20261013）

## 更新重点


- EP v5/v6 融合 MoE 支持按每来源接收配额分块：完整输入只打包一次，逐轮复用接收和计算空间，实际轮数由首轮通信头协商，在同一 stream 上跳过无效轮次。插件新增 `VLLM_XCPU_MOE_EP_MAX_RECV_TOKENS_PER_RANK`，默认 1024，设为 0 关闭分块。
  - 如果 `USER_VLLM_MAX_NUM_BATCHED_TOKENS` 较大，建议开启，一般建议设置为 `USER_VLLM_MAX_NUM_BATCHED_TOKENS / TP_SIZE`
- `moe_unpermute` 的加权归约改为每个 worker 使用一行 FP32 累加空间，移除调用方的 `[容量,H]` FP32 workspace；普通 fused MoE、EP v5/v6 和 AF F 端 v7/v8 同步调整接口及空间布局。
- MCPU 新增 stream 产生条件标志的 kernel launch 和调用级生命周期管理；修复 blocking worker 丢失唤醒及并发 profiler 槽位分配。队列内联任务空间从 256 字节增至 480 字节，需配套重编运行时、扩展和编译缓存。
- vLLM 在二维连续 BF16/FP16/FP32 的 MCPU 编译路径中使用动态 padding 和显式 `as_strided` 完成 sequence parallel chunk，避免原自定义入口的 Python fallback。运行期 dummy 标志移至 worker，覆盖 target/draft forward，解除 DP>1 和单 token 限制，保留 profiling/warmup 的正常计算。
- vLLM 编译因子最终保留 DP rank 差异，仅继续忽略 RPC ready base port 等既有通信地址因子；开发套件默认拆分编译 C++ wrapper 并使用 O1，以缩短 wrapper 编译时间。

## 备注

临时测试记得设置 VLLM_XCPU_ENABLE_FUSED_EP_MOE=0 ，先不开融合接口版本。后续需要正式适配 fused_ep_moe v5/v6/v7/v8 目前已完成 chunking 和 workspace，其他功能还未稳定。

## torch_xcpu 算子变更

统计范围为上一版基线 `5be2f74dee66e86e68dac82822f71ff97c0e08db`（不含，2026-10-10 发布快照）至 `2283e815dad22ced19919ceaf0ac5d133261fb2b`（含，2026-10-13 发布快照），按 Git 提交拓扑统计。本次未另行指定交付后区间或排除模块。测试用于佐证行为，但不代表覆盖全部 shape、dtype、后端和并行组合；本次文档打包未重新运行算子或端到端测试。

下文记 P 为 EP rank 数、M 为 SP 后每 rank 输入上限、H 为 hidden size、T 为 TopK、E 为本地专家数。配额 Q=0 时 C=M，否则 C=min(M,Q)；仅 C<M 时启用分块。分块接收容量为 P*C 行，计算路由容量为 P*C*min(T,E)，路由索引仍预留 P*C*T。完整发送记录、返回索引和源端 FP32 `[M,H]` 跨轮累加空间保留到本次调用结束，不能按 C 截断。

### 涉及算子 impl 级修改

本节按提交到 MCPU stream 的独立任务实现是否改变分类，包含计算、通信和控制任务。条目涉及的 schema、包装及 workspace 配套变化一并保留；不以文件是否位于 torch_xcpu_impl 目录作为唯一依据。

- `moe_prepare_hybrid_pack_v5_v8`（中等修改）：内部 Args/State 新增实际发送字节容量、chunk_rows、source_rounds 和共享 chunk_plan；xthd kernel 新增 Chunked 模板分支。分块时始终使用 dense 布局，一次对完整输入计数、打包，同一 token 到同一目标的多个专家仍合并为一条记录。每 C 条记录的块首两个 int32 改为 `[本块记录数, source_rounds]`，空目标发送共享的 `[0, source_rounds]` 共 8 字节；IDs/weights/hidden 偏移不变，返回索引保持 `dest*M+ordinal`。未分块固定槽选择收紧为实际行数不超过 min(128,容量)，dense 路径在写入前校验目标记录数及实际发送容量。无新增独立 Torch schema，NPU pack 实现须同步参数、模板实例及 wire layout。

## 接入与发布备注

- 先更新并重编 torch_mcpu，再重编 torch_xcpu、torch_mpi_ext，并配套安装插件、应用 vLLM patch。torch_mpi_ext 本次无新提交，但受 MCPU 队列头文件 ABI 变化影响仍需重编。旧 JIT/Inductor 产物需重新生成；本次打包未修改本地构建选项或执行构建。
- 插件配额默认 1024，底层执行和容量查询 schema 默认 0；二者不可混淆。Q 不再除以 SP，实际 C 会截断至 SP 后的输入上限 M；所有参与 EP 的 rank 应使用一致配置。该选项只作用于融合 EP v5/v6，与 v4 总接收容量、AF v7/v8 无关；原 `VLLM_XCPU_ENABLE_FUSED_EP_MOE=0` 仍可关闭融合入口选择。
- 条件 launch 依赖同一 stream 内产生和读取标志，拒绝跨 stream 提交及非空嵌套条件。MPI 窗口仍为进程级上下文，共享窗口的调用须按 collective 顺序执行到最终归约；调用级状态并不提供多流重叠通信能力。profiler 槽位原子预留支持多提交线程，reset/snapshot 仍须停止提交并等待 stream 完成。
- `VLLM_XCPU_ENABLE_DUMMY_RUN_FAST_PATH` 默认仍为 1，运行期 dummy batch 保持必要通信；新增测试 `vllm/tests/v1/worker/test_gpu_model_runner_v2_eplb.py` 覆盖 DP=1/2、decode 长度 1/5、运行期/关闭/profile/warmup 的 target 与 draft 标志。SP chunk 本次未新增对应专项测试。
