# 20261105 更新说明（20261029 至 20261105）

注意！

- 本次只有 `torch_xcpu`、`vllm-xcpu-plugin` 和 `vllm-xcpu-dev-kit` 有提交。**vLLM、torch_mcpu、torch_mpi_ext、PyTorch 均无变化，本次不提供 vLLM patch**，20261029 的 vLLM patch 和两个 PyTorch patch 继续有效。
- `fused_mla_qnorm_qb_uk_rope_cache` 的默认实现版本是 A3（mega-kernel）。**在 `USE_ACCELERATOR` 构建上，`mk/arch/npu` 全部是 `MK_TODO` 占位，执行到即 `std::abort`，不会抛出 Python 异常。** 插件开关 `VLLM_XCPU_FUSED_MLA_QNORM_QB_UK` 默认为 `0`（关闭），因此默认部署不会走到这条路径；NPU 上在 `mk/arch/npu` 或 B0 落地之前不要打开该开关，确需试用时设 `TORCH_XCPU_FUSED_MLA_QNORM_QB_UK_ROPE_CACHE_IMPL=A1` 走逐算子序列。
- mega-kernel 硬件层中 RMA 广播、`PeMask` 位序、`rma_iput` 到自身等一批接口是**按推测编写的**，清单见 `torch_xcpu/docs/mega-kernel/arch-layer.md` §4「待硬件确认项」（共 8 项），接入前需要硬件团队逐条确认。
- `torch_xcpu` 删除了 `torch_xcpu::prepack_linear_weight` 和 `torch_xcpu::linear_prepacked_out` 两个 Torch 算子，以及 `torch_xcpu.ops` 中的 `prepack_linear_weight` / `linear_prepacked` / `can_prepack_linear_weight` / `check_prepack_linear_weight`。本仓库和插件中没有调用方，外部如有直调需要迁移到新的 BF16 linear 接口（见下文）。

## 更新重点

- **GLM-5.2 MLA 前半段融合为单个算子（mega-kernel 首个落地算子）**：新增 `torch_xcpu` 算子 `fused_mla_qnorm_qb_uk_rope_cache`，把 q/kv RMSNorm、FP8 `q_b_proj`、`W_UK_T` 乘法、RoPE 和 KV cache 写入合成一次调用。目标形状是 GLM-5.2 TP4（每 rank 16 头，nope 192 / rope 64 / kv_lora 512 / q_lora 2048）。`num_tokens <= 16` 走 mega-kernel，更多 token 时在算子内部退回逐算子序列，因此 eager 和 `torch.compile` 都可用。插件侧由 `VLLM_XCPU_FUSED_MLA_QNORM_QB_UK` 控制（默认关闭），权重加载后再按 FP8 后端和形状决定是否启用。**B0 目前是占位。**
- **重建 mega-kernel 硬件抽象层 `mk/arch`**：host 与 device 分成两个编译单元，提供异步 DMA/RMA、广播（`PeRange` / `PeMask`）、RMA 广播、DMA 优先级提示和 per-PE phase 计数。x86 用 xthd 线程模拟实现，**NPU 侧 `arch/npu/{device,host,types}.h` 全部是 `MK_TODO` 占位**。硬件常数在 `mk/arch/config.h`：96 PE = 2 sub-die × 48，每簇 2 PE，DMA 4 B 对齐，tile 对齐 128 B。
- **DeepSeek-V4.1 算子基础**：新增 MoE gate `deepseek_v41_topk_softplus_sqrt`、分组 W8A16 投影 `einsum_fp8_tgd_grd_to_tgr`、带 clamp 的 SwiGLU `silu_and_mul_with_clamp`，并把 `swiglu_limit` 贯通到 fused MoE 各路径；FP8 linear 接受 MXFP8 的 32×32 UE8M0 块 scale。这些是 V4.1-Flash 的前置算子，**B0 分支均为占位或需要跟进**。
- **BF16 linear 正式化为后端族**：用 `Bf16LinearBackend`（`INTEL_AMX` / `ONEDNN` / `PORTABLE` / `ACC`）、初始化期 prepack 和每后端的 dispatcher 算子，替换原来只有 ACC 的 `prepack_linear_weight` / `linear_prepacked` 一对算子。契约为 `out = input @ W^T (+ FP32 bias)`、FP32 累加，输出 BF16 或直接保留 FP32 累加器（router logits、V4.1 compressor kv/score 投影）。**`AccBf16LinearKernel` 是新的 B0 边界，当前全部转发 portable 参考实现。**
- **GLM-5.2 TP4 测试与压测工具**：新增 GLM-5.2-FP8 DP1/TP4 的 eager / compile 预设、dummy 7 层预设、TP4 compile DFlash2 预设，以及一次启动跑完单流/多流 × 0.5K/4K 的 `run_vllm_test.sh --suite-test`。bench 脚本现在给每次运行生成唯一 `cache_salt`，避免重复运行互相命中 prefix cache 导致 TTFT/吞吐不可比。

### 影响 B0 算子实现

- `fused_mla_qnorm_qb_uk_rope_cache`（新增算子）：MLA 前半段融合算子，计算 `q_c_norm = rms_norm(qkv[:, :2048])`、`kv_c_norm = rms_norm(qkv[:, 2048:2560])`、`q = q_c_norm @ dequant(W_qb)^T`（每头 192 列 q_nope + 64 列 q_pe）、`out_q[:, :, :512] = q_nope @ W_UK_T`、`out_q[:, :, 512:] = rope(q_pe)`，并写入 `kv_cache[slot] = kv_c_norm | rope(k_pe)`。
  - Torch schema：`fused_mla_qnorm_qb_uk_rope_cache(Tensor(a!) qkv, Tensor q_a_weight, Tensor kv_a_weight, float q_a_eps, float kv_a_eps, Tensor w_qb, Tensor w_qb_scale, int fp8_backend, Tensor w_uk_t, Tensor positions, Tensor cos_sin, Tensor slots, Tensor(b!) kv_cache, bool fp8_ds_mla, bool is_neox, Tensor(c!) q_c_norm, Tensor(d!) kv_c_norm, Tensor(e!) q, Tensor(f!) out_q) -> ()`。launch impl 参数结构为 `fused_mla_qnorm_qb_uk_rope_cache_arg_t`（`torch_xcpu_impl/include/fused_mla_qnorm_qb_uk_rope_cache.h`），全部是裸指针、stride 和标量。
  - 形状为固定特化（常量见 `kFusedMlaQnormQbUkRopeCache*`），契约如下：
    - `qkv`：BF16 `[T, 2624]`，`stride(1) == 1`。
    - `q_a_weight` / `kv_a_weight`：连续 BF16 `[2048]` / `[512]`。
    - `w_qb`：线性后端 `initialize_fp8_linear` 产出的 packed FP8 权重，逻辑形状 `[4096, 2048]`，**不是 checkpoint 布局**，具体格式只由 `fp8_backend` 决定。
    - `w_qb_scale`：连续 FP32 `[32, 16]`，即 128×128 块 scale。
    - `w_uk_t`：连续 BF16 `[16, 192, 512]`。
    - `positions`：连续 int64 `[T]`；`slots`：连续 int64 `[<= T]`。`slot < 0` 或 `t >= num_slots` 的 token 不做 RoPE，也不写 cache。
