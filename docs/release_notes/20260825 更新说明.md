20260825 更新说明（20260806 至 20260825）

更新重点：
- 正式支持 GLM-5.2 的 DSA (Sparse MLA)
- 新增 `fp8_ds_mla` KV cache：BF16 MLA latent 按 128 元素分组量化为 E4M3FN，使用 `[blocks, block_size, 656]` uint8 cache，同时支持 dense/sparse unified attention；编码已对齐 Triton 的 RNE + satfinite 语义。
- 实现 MoE EP MPI v6 prepare/finalize：支持 BF16/FP32、top-k 6/8、xthd pack/unpack/reduce 与 `alltoallv_put`，需要实现 3 个从核算子。作为 AFD 分离之前的核心 EP 方案 !
- 补齐 DFlash/预测解码使用的 `argmax_out`、rejection logits stats 和 rejection resample 算子，并迁出 torch_mcpu 中的旧实现。
- 新增 Qwen3.6 多模态支持，需要实现 2 个从核算子，但其中一个是 SDPA (常规 Attention, 不是 Paged Attention)
- FP8 linear、MXFP4 linear、MoE grouped GEMM 与 fused MoE 改为具名 concrete backend schema，修复 AOTI wrapper 生成并明确 prepack/compute 后端所有权。
- 通信：
	- `torch_xcpu` 新增 `all_gatherv_into_tensor_out_v2`
	- `torch_mpi_ext` 新增 reduce_scatter/reduce_scatterv；	
- 开发套件补充 GLM-5.2、MoE alltoallv-v6 和 Qwen3.5 多模态测试配置。

# torch_xcpu 算子变更：

统计范围为上一发布点 `c33f5e9f5d9895d169d7a4e96f749a0deb685bbb`（不含）至 `8392ebdb8cd69a5d578844fb9d6ca1df3479ed8b`（含）。以下按发布终点的接口和实现整理；测试用于佐证行为，但不代表已覆盖全部 shape、dtype、后端和并行组合。

本区间还将所有已登记算子的实现选择从精确版本号改为 implementation family（A/B）分派，使同一 family 内的后续版本复用同一路径；该提交不改变单个算子的外部 schema 或数值契约，因此不拆成算子条目。
	- commit `f3b83df41c7fb865b4a011001fd9eb84ad8166eb`：[Core] dispatch operators by implementation family

- `layer_norm`（新增算子）：新增 BF16/FP32 LayerNorm，输入支持连续 Tensor 或最后一维连续的 row-strided 2D Tensor；weight/bias 固定为连续 FP32 一维 Tensor，输出与输入同 shape、同 dtype。
	- commit `14fa718a0a45b3bfa1a39d757771497a73e59b7b`：[Norm] impl layer_norm
	- 测试：`torch_xcpu/test/ops/custom_ops/test_layer_norm.py`
- `per_token_group_quant_fp8`（新增算子）：对二维 BF16/FP32 输入按最后一维 group 动态量化，输出 E4M3FN Tensor 和 `[rows, columns/group_size]` FP32 scale；支持普通 scale 与 UE8M0 scale 模式。
	- commit `95cabc27a727627dd0851ba738ca5606f619d51c`：[Quant] impl per_token_group_quant_fp8

	- commit `80a19fd6150587927b9042dabf2c4a320a6de7a6`：[DSA] basically support sparse_mla and sparse_indexer
	- 测试：`torch_xcpu/test/ops/custom_ops/test_sparse_indexer.py`

	- 测试：`torch_xcpu/test/ops/custom_ops/test_sparse_indexer.py`

	- commit `80a19fd6150587927b9042dabf2c4a320a6de7a6`：[DSA] basically support sparse_mla and sparse_indexer
	- 测试：`torch_xcpu/test/ops/custom_ops/test_sparse_indexer.py`

- `sparse_mla_decode`（请忽略）
- `build_indexer_prefill_chunk_metadata`（新增算子）：根据 query slice、DCP rank/world/interleave 与压缩比，生成 token-to-sequence、row start/end 和压缩序列前缀和等 int32 metadata。
	- commit `80a19fd6150587927b9042dabf2c4a320a6de7a6`：[DSA] basically support sparse_mla and sparse_indexer

- `all_gatherv_into_tensor_out_v2`（新增算子）：新增可变长度 MPI all-gather，按 `sizes` 将各 rank 输入拼接到预分配 output，支持显式通信指针包装和目标维度。
	- commit `7e9fd6ab26d847750b185296430f63307ba21c03`：[MPI] impl all_gatherv_into_tensor_out_v2
	- 测试：`torch_xcpu/test/mpi_custom_ops/test_all_gather_into_tensor_out_mpi.py`
- `moe_prepare_fused_v6`（新增算子）：按目的 expert 打包 hidden/top-k/return-row metadata，通过单次 `alltoallv_put` 分发后解包；最终 xthd 实现支持 BF16/FP32、top-k 6/8，并要求 hidden payload 和记录保持 4-byte 对齐。需要实现其中2个从核算子。
	- commit `0bf2c0c486397ed81961a45976733027d7156c1f`：[MoE][EP] impl moe_prepare / finilize v6 with topk and alltoallv_put support

- `moe_finalize_v6`（新增算子）：将 expert 输出按二维 return-row indices 通过 RMA 返回源 rank，并在 FP32 workspace 中归约到 BF16/FP32 output；提供 collective cleanup 接口释放 MPI window。需要实现其中1个从核算子。
	- commit `0bf2c0c486397ed81961a45976733027d7156c1f`：[MoE][EP] impl moe_prepare / finilize v6 with topk and alltoallv_put support
	- commit `fa716adadb35deabfb51a2789314eaaec3be8c85`：[MoE][EP] impl xthd version kernels for moe alltoallv v6
	- 测试：`torch_xcpu/test/mpi_custom_ops/test_moe_prepare_fused_v6_finalize_v6_roundtrip_mpi.py`
- `unified_attention`（大修改）：新增可选 int32 `logical_topk[num_tokens, topk_tokens]` 以支持 sparse MLA；随后新增 `kv_cache_dtype="fp8_ds_mla"` 路径，接收 BF16 query `[tokens, heads, 576]`、uint8 cache `[blocks, block_size, 656]` 并输出 BF16 `[tokens, heads, 512]`，dense/sparse 均可用。xthd 普通路径还将 tile token 维固定为 16 并模板化矩阵乘维度，partial tile 通过补零和 `-inf` mask 保持数值语义。

	- commit `bd142fe2596e4c191997a6f98fa7b6b9c98d00ca`：[Attn] Support kv_cache_dtype: fp8_ds_mla (#37)

	- 测试：`torch_xcpu/test/ops/custom_ops/test_unified_attention.py`
- `reshape_and_cache`（大修改）：公共包装新增 `kv_cache_dtype="fp8_ds_mla"` 分派，将 BF16 MLA latent `[tokens,512]` 按 128 元素分成四组量化，连同四个 FP32 scale 和 64 维 BF16 RoPE 写入 656-byte cache entry；最终编码采用与 Triton `cvt.rn.satfinite` 一致的 E4M3FN round-to-nearest-even 和有限值饱和语义。
	- commit `bd142fe2596e4c191997a6f98fa7b6b9c98d00ca`：[Attn] Support kv_cache_dtype: fp8_ds_mla (#37)

	- 测试：`torch_xcpu/test/ops/custom_ops/test_reshape_and_cache.py`
- `argmax_out`（新增算子）：为预测解码 logits 新增预分配输出接口；当前从核契约为二维连续 BF16 输入、偶数且非空 vocabulary、`dim=-1`、`keepdim=False` 和连续 int64 output。
	- commit `dd63fd932affc6047b140e0a07ee4a0a0ac1bc86`：[SpecDecode] impl rejection_resample, rejection_compute_local_logits_stats, argmax_out
	- 测试：`torch_xcpu/test/ops/custom_ops/test_argmax_out.py`
- `vllm_rejection_compute_local_logits_stats`（新增算子）：计算 DFlash rejection sampling 所需的 target argmax/max/sumexp 与 draft max/sumexp，支持可选 draft logits 和 expanded request/position mapping。
	- commit `dd63fd932affc6047b140e0a07ee4a0a0ac1bc86`：[SpecDecode] impl rejection_resample, rejection_compute_local_logits_stats, argmax_out
	- 测试：`torch_xcpu/test/ops/custom_ops/test_rejection_sampler.py`

	- commit `dd63fd932affc6047b140e0a07ee4a0a0ac1bc86`：[SpecDecode] impl rejection_resample, rejection_compute_local_logits_stats, argmax_out
	- 测试：`torch_xcpu/test/ops/custom_ops/test_rejection_sampler.py`
- `scaled_dot_product_attention_varlen`（新增算子）：新增 packed `[tokens, heads, embedding]` variable-length SDPA，使用 int32 contiguous `cu_seqlens_q/k`，支持 FP16/BF16/FP32、MHA/GQA、causal 与 cross attention；仅用于 inference，要求 `dropout_p=0` 且不接受 dense mask。后续将 online softmax 的 max/sum/scale 循环向量化。
	- commit `f4003f1f7e3a8ce64a6cf7435b54d36e23d4b497`：[Attn] impl sdpa_varlen_xthd
	- commit `b95100d4deee37a795e185a7d0a798fb67b3ac14`：[Attn][Opt] Vectorize SDPA online softmax
	- 测试：`torch_xcpu/test/ops/custom_ops/test_sdpa.py`
- `qwen3_vl_bilinear_pos_embed`（新增算子）：对二维 FP32/BF16 position embedding 执行 Qwen3-VL 双线性空间插值并按 spatial-merge 顺序输出 `[temporal_size*height*width, hidden_dim]`；同时提供预分配 out 接口。最终接口允许 requires-grad 输入但仍只注册推理后端实现。
