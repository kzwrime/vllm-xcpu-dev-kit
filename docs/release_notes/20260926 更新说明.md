# 20260926 更新说明（20260923 至 20260926）

## 更新重点

- DSA 新增 `fused_indexer_qk_rope_quant_cache`，融合 Q RoPE/权重缩放与 K LayerNorm/RoPE/FP8 cache 写入；插件接入融合路径，并将 `indexer_k_cache` 改为普通注册算子以移除该处 torch.compile Python fallback。
- FP8、MXFP4 linear 和 MoE grouped GEMM 新增后端权重存储容量查询及 `padding_example` 后端；逻辑 shape 保持不变，物理 padding 由后端管理。
- MoE prepare/finalize v5 改用固定容量记录与从核 pack/unpack/reduce，通信采用 `MPI_Alltoall` 和 `MPI_Alltoallv`；Python 接口和底层 Torch ABI 均有变化
- 新增 `moe_scaled_add`，将 routed 输出缩放和 shared 输出相加融合，保留 BF16 中间舍入；补齐 add、mul、fill 的部分 ATen 变体，并扩展 einsum 的输出 stride 支持。
- vLLM 的 XCPU DSA 路径跳过 top-k 索引缓冲区预清零；测试改用非哨兵初值，检查算子完整覆盖短行及空行输出。

## torch_xcpu 算子变更

统计范围为上一版基线 `4580a65dfafa6b5b6eb5e1289a1445e405f3375d`（不含，2026-09-23）至 `1acd7698f9b780b7176bc226f1bf7be3ca284fab`（含，2026-09-26）。以下测试用于佐证行为，不代表覆盖全部 shape、dtype、后端和并行组合。

- `fused_indexer_qk_rope_quant_cache`（新增算子）：新增 Python functional 包装与底层 `fused_indexer_qk_rope_quant_cache_out`，输出 BF16 Q 和 FP32 weights，原地写 FP8 K cache。Q 为 BF16 `[T,H,128]`，H 支持 1/2/4/8/16/32/64；K 为 BF16 `[T,128]`，norm weight/bias 为 FP32，融合入口的 rotary_dim 为 64，page size 为 64/128。cache 为逻辑 `uint8 [P,B,132]`，页内分别存 FP8 值和 FP32 scales；slots 可短于 padding 后的 token 数，负 slot 仅跳过 K 写入。小负载在一次 launch 内按 K 行和 Q head tile 分工，大负载按启发式切回 Q、K 两次有序 launch；NPU 团队需实现对应调度，不能假设始终单 launch。输出不得与输入或彼此别名。

  - commit `8993144fc6627353a1a4090c407c8159894d87b5`：[DSA] impl fused_indexer_qk_rope_quant_cache as horizontal fusion of fused_indexer_k_norm_rope_cache and fused_indexer_q_rope_quant
  - 测试：`torch_xcpu/test/deepseek_v32/test_indexer_fused_k.py`

- `fused_indexer_q_rope_quant`（中等修改）：底层改用 `IndexerQArgs` 和编译期 head 数、rotary_dim、布局、cos/weights dtype 分派，配置在 launch 前确定，供独立与融合路径共享。支持 H=1/2/4/8/16/32/64、D=128，以及 2 至 128 的偶数 rotary_dim；tail RoPE 仅支持 GPT-J 布局。Torch schema 不变，底层 C++ 接口需配套更新。

  - commit `8993144fc6627353a1a4090c407c8159894d87b5`：[DSA] impl fused_indexer_qk_rope_quant_cache as horizontal fusion of fused_indexer_k_norm_rope_cache and fused_indexer_q_rope_quant
  - 测试：`torch_xcpu/test/deepseek_v32/test_indexer_fused_k.py`

- `fused_indexer_k_norm_rope_cache`（中等修改）：底层改用 `IndexerKArgs`，将单行 kernel 提取为共享模板；page size、UE8M0 标志、RoPE 布局与 cos dtype 在 launch 前分派。保留 row-strided K、页间 padding、短 slots、负 slot 跳过写入及 BF16 阶段舍入语义；Torch schema 不变，但从核参数接口改变。

  - commit `8993144fc6627353a1a4090c407c8159894d87b5`：[DSA] impl fused_indexer_qk_rope_quant_cache as horizontal fusion of fused_indexer_k_norm_rope_cache and fused_indexer_q_rope_quant
  - 测试：`torch_xcpu/test/deepseek_v32/test_indexer_fused_k.py`

- `fp8_linear`（小修改）：新增 `fp8_packed_weight_storage_bytes_<backend>(N,K)`，初始化按后端返回容量分配存储，逻辑 tensor 仍为 `[N,K]`。新增 `padding_example`：K 为 2 的幂时每行增加 128 Byte，否则无 padding。prepack 与 compute 必须遵守同一物理布局；底层 out 直调需自行分配足够存储，普通 clone 会丢失额外容量。原有后端容量仍为 N*K Byte。

  - commit `68da06bef37f51f7b3912f05f2edc40d48a213d2`：[Linear] support padding_and_packed_weight for fp8/mxfp4 linear
  - 测试：`torch_xcpu/test/ops/gemm_ops/test_fp8_linear.py`

- `mxfp4_linear`（小修改）：新增 `mxfp4_packed_weight_storage_bytes_<backend>(N,K/2)`，逻辑 packed uint8 tensor 仍为 `[N,K/2]`。新增 `padding_example`：packed 行宽 K/2 为 2 的幂时每行增加 128 Byte；scale 的 packing 不变。容量查询、prepack、compute 必须配套，低层直调与复制 packed tensor 需注意额外存储。

  - commit `68da06bef37f51f7b3912f05f2edc40d48a213d2`：[Linear] support padding_and_packed_weight for fp8/mxfp4 linear
  - 测试：`torch_xcpu/test/ops/gemm_ops/test_mxfp4_linear.py`

- `moe_grouped_gemm`（小修改）：新增 `moe_grouped_gemm_packed_weight_storage_bytes_{ClassName}(E,N,packed_K)`，将权重容量与 prepare 的 scratch 容量分离，逻辑 shape 保持 `[E,N,packed_K]`。新增 FP8/MXFP4 padding_example 后端；ACC FP8/MXFP4 的容量、expert 间距与逐 expert prepack 跟随对应 ACC linear 后端规则。不能用逻辑 numel 推断实际容量或跨后端混用 packed 权重，后端接入需同步更新容量与读写规则。

  - commit `68da06bef37f51f7b3912f05f2edc40d48a213d2`：[Linear] support padding_and_packed_weight for fp8/mxfp4 linear
  - 测试：`torch_xcpu/test/ops/gemm_ops/test_moe_grouped_gemm.py`、`torch_xcpu/test/ops/custom_ops/test_fused_moe_backends.py`

- `moe_prepare_fused_v5`（大修改）：Python 与 BF16/FP32 Torch schema 同步替换为 `return_row_indices [M,topk]`、按来源 rank 的接收元素数/偏移、按目标 rank 的发送行数和一维 uint8 dispatch buffer，移除旧的 expert_num_tokens 及分离发送缓冲区。按目标 rank 固定容量打包，先 Alltoall 交换计数，再 Alltoallv 传输，最后从核解包；支持 topk=6/8、EP<=128，hidden 行字节数须能被 4 整除。新增集体 cleanup 入口释放 MPI window；旧直调参数不兼容，插件必须配套升级。

  - commit `977cdd65aa336c59fc28243a63baf1a837f3d214`：[MoE][EP] impl moe_prepare / finalize v5 based on v6, using alltoall + alltoallv instead of alltoallv_put
  - 测试：`torch_xcpu/test/mpi_custom_ops/test_moe_prepare_fused_v5_finalize_v5_roundtrip_mpi.py`

- `moe_finalize_v5`（大修改）：Python 与 BF16/FP32 Torch schema 改用二维 return_row_indices 及接收元素数/偏移，增加 `max_num_input_rows`，移除外部 recv_hidden_states 参数。Alltoallv 回传结果后由从核按原 token 行归约，使用 FP32 workspace；topk=6/8、EP<=128，返回窗口容量按 `min(topk,EP)*max_num_input_rows` 计算。新增集体 cleanup 入口，调用方和从核参数结构均须更新。

  - commit `977cdd65aa336c59fc28243a63baf1a837f3d214`：[MoE][EP] impl moe_prepare / finalize v5 based on v6, using alltoall + alltoallv instead of alltoallv_put
  - 测试：`torch_xcpu/test/mpi_custom_ops/test_moe_prepare_fused_v5_finalize_v5_roundtrip_mpi.py`

- `add`（中等修改）：扩展 `aten::add` 的 out、Tensor inplace、Scalar functional/out/inplace 入口；底层增加 ScalarRight 模板分支。符合 BF16/FP32、rank<=4、对齐和尺寸策略且 alpha=1 时使用从核，输出要求地址唯一、末维连续，别名仅接受相同视图；不符合条件回退原 kernel。BF16 scalar 路径先将标量舍入为 BF16。

  - commit `bac7dcc099638ca31c617c3ef6b2892c799bab3d`：[Aten] impl more basic aten kernels
  - 测试：`torch_xcpu/test/ops/aten/test_binary_variants.py`、`torch_xcpu/test/ops/aten/test_add.py`

- `mul`（中等修改）：扩展 `aten::mul` 的 out、Tensor inplace、Scalar functional/out/inplace 入口，复用现有从核和新的输出布局/别名检查。不满足 dtype、rank、对齐和尺寸策略时回退；小 shape 的 Scalar inplace 通过 CPU scalar tensor 与 out 路径处理，避免原 composite 路径尝试创建 CPU 标量的 mcpu view。

  - commit `bac7dcc099638ca31c617c3ef6b2892c799bab3d`：[Aten] impl more basic aten kernels
  - 测试：`torch_xcpu/test/ops/aten/test_binary_variants.py`、`torch_xcpu/test/ops/aten/test_mul.py`

- `fill`（小修改）：新增 `aten::fill_.Tensor` 接入，接受 CPU 或同设备零维单元素 value，取出标量后在满足原有一维连续 int32、对齐和尺寸策略时调用 fill 从核，否则回退。未新增底层计算核。

  - commit `bac7dcc099638ca31c617c3ef6b2892c799bab3d`：[Aten] impl more basic aten kernels
  - 测试：`torch_xcpu/test/ops/aten/test_binary_variants.py`

- `einsum_mhk_hkn_to_mhn`（小修改）：除连续 `[M,H*N]` 外，输出支持末维连续、head/token 行互不重叠的 `[M,H,N]` 视图，按实际 output stride 写入。保留 H 为正 8 倍数、K 为正 64 倍数、N 为正 32 倍数的模型约束。实现版本选择下移至 impl 层，独立与融合调用均遵守同一选择；B0 从静默返回改为明确报错，Torch schema 不变。

  - commit `98cb6d72b7fea33d088bb06a272e21585c57af70`：[DSA] update einsum_mhk_hkn_to_mhn
  - 测试：`torch_xcpu/test/ops/custom_ops/test_einsum_mhk_hkn_to_mhn.py`、`torch_xcpu/test/deepseek_v32/test_fused_mla_rope_qproj_cat_cache.py`

- `moe_scaled_add`（新增算子）：新增 functional 包装和 `moe_scaled_add_out(output,shared,routed,scale)` Torch schema。输入和输出为同设备、同 shape 的连续二维 BF16，output 不得与输入重叠；先将 routed*scale 舍入 BF16，再与 shared 相加并舍入 BF16，保留原先两步计算语义。空输出提前返回；A0 为宽度 6144/4096/2048 提供模板特化，其余宽度走通用实现，B0 未实现。

  - commit `1acd7698f9b780b7176bc226f1bf7be3ca284fab`：[MoE] impl moe_scaled_add to fuse mul and add
  - 测试：`torch_xcpu/test/ops/custom_ops/test_moe_scaled_add.py`

补充核对：v6 prepare 在该区间仅调整局部变量命名与排版，未改变接口或算法，不作为独立行为变更。top-k 仅加强测试初值检查，未修改对应计算核。
