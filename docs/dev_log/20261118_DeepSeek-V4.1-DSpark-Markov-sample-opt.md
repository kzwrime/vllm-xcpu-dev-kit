# DeepSeek-V4.1 DSpark Draft Markov 5 步采样融合优化（`A0` / `mk A1` / `FP8` / `INT8`）

## 1. 背景及分析

在 `DeepSeek-V4.1-Flash` 的 DSpark（`dspark_block_size = 5`）投机解码路径中，`base_logits [B, 5, 129280]` 由一次并行前向算出，而 `DSparkSpeculator._sample_sequential` 的 Markov 转移头严格按 5 步串行执行（`markov_w1[129280, 256]` 查表 $\to$ `markov_w2[129280, 256]` 投影 $\to$ 加 `base_logits` $\to$ `argmax`/`gumbel_sample` $\to$ 回写 `prev`）。

原逐算子（op-by-op）路径存在两类主要开销：
1. **Launch 与步间同步开销**：每步 5 个内核 $\times 5$ 步 = **25 次 MCPU kernel launch**（含 Python 调度与多次 OpenMP fork/join）。
2. **大词表中间张量反复读写 HBM**：虽然 `markov_w2` 权重仅在 HBM 存 1 份，但因步间存在 `prev_id` 自回归依赖且全量权重（BF16 `63.125 MiB`）远超单 PE 可用 SRAM（`387,072 B` arena），5 步必须流式扫描 5 遍 `markov_w2`；逐算子方案在此基础上还额外每步产生 `[B, 129280]` `bias` 和 `logits` 的全词表读写。

详细推导与原 trace 拆解见 [`torch_xcpu/docs/deepseek_v41/dspark_markov_sample.md`](../../torch_xcpu/docs/deepseek_v41/dspark_markov_sample.md)。

## 2. 方案及效果评估

### 2.1 三级执行路径与默认策略

| 路径 | 开关 / 版本 | 说明 |
|---|---|---|
| **逐算子 Fallback** | `VLLM_XCPU_DSPARK_MARKOV_FUSED=0` | 完全跳过融合内核与加载期量化，保留 `markov_w2._xcpu_bf16_linear`，执行 `markov_embed -> markov_bias -> add_ -> _sample_logits` |
| **`A0` OpenMP 融合（默认）** | `TORCH_XCPU_DSPARK_MARKOV_SAMPLE{,_FP8,_INT8}_IMPL=A0` | 单次 kernel launch + 单 OpenMP 并行区，按词表列分块（`BlockN=32`）片上融合，兼容任意 `OMP_NUM_THREADS` |
| **`A1` 96-PE Mega-Kernel（`mk`）** | `TORCH_XCPU_DSPARK_MARKOV_SAMPLE{,_FP8,_INT8}_IMPL=A1` | 96-PE（2 Sub-Die $\times 48$ PE）真融合（需 `OMP_NUM_THREADS >= 96`、`markov_rank == 256`、`draft_vocab % 64 == 0` 且 4B DMA 对齐） |

### 2.2 Mega-Kernel（`A1` / `mk`）与 `FP8` / `INT8` `[32, 32]` UE8M0 设计要点

1. **低优先级双缓冲 DMA 与首块冷启动隐藏**：每步 `StepSetup` 在高优先级 `embed`/`meta` 广播前先以 `DmaPriority::Low` 提前挂出第 0 块 `w2` 与 `base_logits` 预取；步内按 `BlockN=64` 做 Ping-Pong 双缓冲。
2. **两级 Sub-Die RMA 规约 + 单次全局 `barrier()`**：48 PE 先用片上 `rma_iput` 汇总至各自 Sub-Die leader（PE `0` / PE `48`），HBM `partial_workspace` 写入从 $96 \times 256\text{ B} = 24\text{ KiB}$ 缩减为 **$2 \times 256\text{ B} = 512\text{ B}$**；全核仅做 **1 次** `barrier()`，两 leader 对称读回 `512 B` 各自冗余归约全局最优 token 后再做 Sub-Die 内 `rma_iput_bcast`，省去第 2 次全局 `barrier()`。
3. **模块化子内核与 `NumReqs > 16` 分块**：拆分 `VecAdd`、`BlockArgmax`、`BlockGumbelMax` 到 `mk/kernels/`；扩展 `mk::kernels::Gemm` 支持第 6 模板参数 `TScale = ue8m0_t`；Host 侧对 `num_reqs > 16` 自动按 `MaxReqs=16` 分块复用同一 `512 B` workspace。
4. **FP8 / INT8 跨步 SRAM 权重常驻 + 尾块双缓冲（预留 `>= 32 KiB` NPU 余量，BF16 保持轻量流式）**：
   - **BF16**（`dspark_markov_sample_device.h`）保持原样轻量 `b[2]` 流式双缓冲（`Sram = 96,896 B` / `RowMajor = 91,904 B`，空闲 `290,176 B` / `295,168 B`），不额外占用常驻槽位。
   - **FP8 / INT8 UE8M0**（独立抽取于 `dspark_markov_sample_quant_device.h`）将 `Gemm_w2::Scratch` 与 `bias` 改为互斥 `union Tmp`，并取消冗余 `draft_out[2]`（改为 `base` 原地叠加并复用 `sig.out` 写回 `draft_logits`），将权重槽 `w2_slots[kWeightSlots]` 移至 `union Stage` 外跨 `step` 持久保留，编译期按 `kArenaBytes - SramReserveBytes`（`32 KiB`）自动算满 **`20` 槽**（`Sram = 352,896 B` / `RowMajor = 352,640 B`，空闲 `34,176 B >= 32 KiB`；`18` 常驻 + `2` Ping-Pong 尾块，$V=129,280$ 下 **`85.5%` 常驻**，5 步 HBM 权重读量从 `157.97 MiB` 降至 **`49.86 MiB`**，`V <= 122,880` 时 **100% 常驻**）。
5. **`FP8 E4M3FN` / `INT8` `[32, 32]` OCP UE8M0 定制算子 + 加载期在线量化**：
   - 新增平行算子 `dspark_markov_sample_fp8` 与 `dspark_markov_sample_int8`（不改动原 BF16 算子）。
   - 插件在 `VLLM_XCPU_DSPARK_MARKOV_DTYPE=fp8|int8` 时，于 `XcpuDSparkSpeculator.load_draft_model` 一次性完成 `[32, 32]` UE8M0 量化与 `layout 1/2/0` 预打包，并释放冗余 `_xcpu_bf16_linear`（省约 `63.1 MiB` 设备内存，一次性开销 FP8 约 `77–86 ms`、INT8 约 `106–113 ms`）。

### 2.3 验证结果摘要

- **独立 `mk` 与加速器检查**：`make -C torch_xcpu/torch_xcpu_impl/test/mk CAT=ops run run-sync accel-check`、`PE=16 SUBDIE=8 CAT=ops run` 以及 `-DUSE_ACCELERATOR` 语法检查全部通过（`accel-check: ok`）。
- **`torch_xcpu` 自定义算子单测**（`test_dspark_markov_sample.py`，含 `V=129,280` 量化常驻+溢出用例）：`A0`（`OMP_NUM_THREADS=32`，默认无告警）**`107 passed in 4.01s`**；`A1`（`OMP_NUM_THREADS=96`）**`107 passed in 5.62s`**。
- **`vllm-xcpu-plugin` lint / mypy / upstream_contracts / unit tests**：`./scripts/check.sh`、`upstream_contracts check/lint/provenance`、`pytest -q tests/upstream_contracts tests/plugin_tests/test_dspark_phase1.py tests/plugin_tests/test_dspark_phase2.py`（`66 passed`）全部通过。
- **端到端与生产尺寸基准**：
  - `DeepSeek-V4.1-Flash-dummy-8-layer-lite` Eager + `--profile`（`OMP_NUM_THREADS=32` `A0`）：`bf16`/`fp8`/`int8` 三档输出一致，MCPU 均耗时分别为 `0.620 ms` / `13.248 ms` / `1.043 ms`；`compile (mode: 3)` + `fp8` 冷编译与请求验证通过（`0.812 s`）。
  - 生产尺寸（`V=129280, r=256, n_spec=5`）`kernel_med`：
    - `A0`（32 线程）：`B=1/8/16` 下 `bf16` 为 `1.20 / 7.08 / 11.02 ms`、`fp8` 为 `18.83 / 81.58 / 157.39 ms`、`int8` 为 `2.57 / 9.99 / 19.74 ms`。
    - `A1`（96 PE 模拟）：`B=1/8/16` 下 `bf16`（流式 Ping-Pong）为 `6.05 / 7.84 / 9.97 ms`、`fp8`（跨步 SRAM 常驻）为 **`3.04 / 5.02 / 7.42 ms`**、`int8`（跨步 SRAM 常驻）为 **`3.04 / 5.05 / 7.46 ms`**（FP8/INT8 相比常驻前 `6.25/6.33 ms` 在 `B=1` 提速超 `2×`）。

## 3. 影响及约束

- **x86 整网默认用 `A0`**：DeepSeek-V4.1 的 `mhc_fused_post_pre_*` 算子在 x86 上要求 `omp_get_max_threads() in {32, 64}`（`vllm_scripts/env.sh` 设为 `32`），不能把全进程 `OMP_NUM_THREADS` 拉到 `>= 96`。因此 `operator_version.cpp` 默认保持 `A0`，避免启动触发 96-PE 警告或 mHC 异常。
- **量化要求**：`VLLM_XCPU_DSPARK_MARKOV_DTYPE=fp8|int8` 需满足 `VLLM_XCPU_DSPARK_MARKOV_FUSED=1`、`draft_vocab_size % 32 == 0`、`markov_rank % 32 == 0` 及无 bias（`DeepSeek-V4.1` 的 `[129280, 256]` 满足）。

## 4. 后续开发

面向真实 **NPU Infra 与算子团队** 的后续工作建议：

1. **在 NPU 平台实现并默认开启 `A1` Mega-Kernel（`mk`）**：
   - `USE_ACCELERATOR` 下硬件固定具备 96 PE，无 x86 OpenMP 线程数与 mHC 冲突限制；建议参考 `torch_xcpu_impl/include/mk/ops/deepseek_v41/dspark_markov_sample{_device,_quant_device,_{fp8,int8}_device}.h` 与 `torch_xcpu/docs/deepseek_v41/dspark_markov_sample.md` 实现真实 DMA/RMA 原语及 `mk/kernels/{gemm,vec_add,block_argmax,block_gumbel_max}/npu.h` 向量化内核，并将 NPU 侧默认版本切至 `A1`（或落地 `B0` 占位）。
2. **评估硬件真实 `FP8 E4M3FN` vs `INT8` 反量化吞吐并择优**：
   - 依据 `torch_xcpu/docs/ops/int8_ue8m0_dequant_simd_design.md` 对比目标硬件 SIMD 上 FP8 转 BF16 与 INT8 `direct_splice_fsub` 位级反量化的指令周期，决定真实部署 `VLLM_XCPU_DSPARK_MARKOV_DTYPE` 默认选型。

## 5. 附录：运行时开关速查

- `VLLM_XCPU_DSPARK_MARKOV_FUSED=1|0`：默认 `1`；设 `0` 手动走逐算子 fallback（不量化且保留 `_xcpu_bf16_linear`）。
- `VLLM_XCPU_DSPARK_MARKOV_DTYPE=bf16|fp8|int8`：默认 `bf16`；设 `fp8`/`int8` 启用 `[32, 32]` OCP UE8M0 加载期量化与低精度融合内核。
- `TORCH_XCPU_DSPARK_MARKOV_SAMPLE{,_FP8,_INT8}_IMPL=A0|A1|B0`：默认 `A0`；设 `A1` 开启 96-PE Mega-Kernel（x86 需 `OMP_NUM_THREADS >= 96`）。
